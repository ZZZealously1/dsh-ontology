# 模板验证与故障处理

本模板用原生 OWL/SWRL 维护模型与规则，用独立案例声明预期。构建脚本只组织和保存源文件；不在 Python 中另写一份业务政策，也不把解析成功当作推理或业务验收成功。运行入口和完整命令见[模板说明](../README.md)。

## 验证要求

| 检查项 | 验证方法与边界 |
|---|---|
| 原生文件、加载清单与集成保真 | 解析每个实际加载的原生模块，核对模块清单；重建集成后按图同构比较，同时检查源快照字节和构建证据，不靠非空或数量相同 |
| 命名空间、UpperCamelCase/lowerCamelCase、标签 | 合成示例测试具名类/属性的命名与标签；业务域 IRI 和命名约定由项目规格说明，不要求匿名类有名称 |
| 类层次 | 循环检查是编辑质量检查；OWL 中循环可能表示等价类，并不自动等于逻辑不一致。真正一致性由声明的 OWL DL 后端检查 |
| 互斥类及间接类型推断 | 完整 TBox/ABox 交给 HermiT，包含间接公理影响；独立负例构造互斥类型冲突并要求报告不一致 |
| domain/range 与 unionOf | 保留原生公理；这些公理用于推断类型，不能以“缺少显式类型”判为 OWL 不一致。需要输入类型完整性时另声明 SHACL |
| hasKey | 原生键使用 RDF 列表；同键可能合并个体，不等于数据库重复报错。测试同键个体再加 `differentFrom`，验证真实矛盾 |
| 枚举 | 保留原生 `allValuesFrom + oneOf`；独立 SHACL 验证输入值域，并用非法枚举案例验证停止 |
| 规则正例、反例和边界 | R01 测敏感/公开；R02 测页数 0/9/10/11。四个合法输入和两个非法输入的预期单独保存，执行实际 SWRL 规则 |
| 固定点 | 对第一次闭包再次运行同一原生 SWRL 通用解释器，检查无新增事实 |
| 源保护与失败状态 | 拒绝覆盖已有构建目录，检测快照篡改，保留数值词法形式；不支持的 `xsd:date` 用临时合成模型验证失败、无一致性结论且不改写源数据 |

测试可证明所列输入与后端的实际行为，不代替真实业务来源审查或项目验收。项目新增公理、规则、数据类型或导入时，应增加对应正反案例并重跑有关检查。

## 显式规则测试范围

`starter` 的 `rule_vocabulary.owl` 是独立维护的普通类/属性模块；`constraints.owl` 保存键、互斥、枚举、最小基数、存在限制、函数属性和并集定义域。`prepare_rule_tests.py` 读取 `tests/runtime-source.ttl`，完整转换被明确选中的词汇模块并逐图同构核对，SWRL 字节原样复制；不能通过删除不支持的公理让模型通过。

这证明的是**选定规则模块、输入与预期的执行**，不是整个 OWL DL + SWRL 联合语义的等价证明。完整两份 TBox 与事实另外运行 OWL DL；完整模型送入 `local-rules-v1` 必须明确失败。项目若依赖键合并、存在推导等完整 OWL 结论再触发规则，须选定经验证支持该联合语义的后端与案例，不能沿用拆分测试声称整体完成。

合成示例中的页数 `10` 只是测试阈值，不来自真实制度；`RestrictedDocument` 分类不构成系统访问权限更改。缺少来源或独立预期的真实规则保留待确认，不用合成示例的测试数量替代业务验收。

## 常见故障

| 现象 | 处理方法 |
|---|---|
| 输出出现 `ontology/ontology` 等层级错误 | 使用明确 `--source` / `--output`；目标末级为 `ontology`，不假定脚本所在业务项目层级 |
| 尝试用不存在的 `Graph.replace` 拼接列表 | 使用 `rdf_authoring.rdf_list` 一次建链；键、枚举和列表使用标准 RDF 列表 |
| 对象属性方向反 | 按主语→谓词→客体核对来源、定义域/值域和实例；来源冲突时先确认，不能根据单个实例自行改业务含义 |
| 一个属性适用于多类主语 | 根据来源决定是否使用 `owl:unionOf` 并集定义域；多条 `rdfs:domain` 表示同时属于多类。后端不支持时记录失败，不能静默删除公理 |
| 检索 TopK 或 RerankTopN 越界 | 核验当前接口实际上下限和参数关系，再设置分页与返回量；不要把其他服务或旧项目的数值作为通用阈值 |
| 中文请求报 `query is empty` | 先检查请求实际非空，再尝试改写措辞；记录请求、改写与失败，限制重试次数 |
| 中文/英文标签重复或无语言标识 | 类 helper 只写指定中文标签；需要其他语言时添加明确语言标签，不混成无语言重复 |
| 功能性属性设在逆方向 | 用一个主语最多能有几个客体核对业务约束。示例 Functional 放在 `hasOwner`（文档→组织），是否至多一个必须由项目来源确定 |
| `inverseOf` 指向未声明属性 | helper 同步声明逆属性和两侧关系；调用方补标签、定义域和值域 |
| 实例合入模型造成双本体头 | ABox 只放事实；构建器拒绝 ABox 本体头，不用 `inst += onto` 混入整个模型 |
| 混淆本体 IRI 与术语命名空间 | 模板本体头使用不带 fragment 的 IRI，术语命名空间以 `#` 结尾；项目可选择其他合法约定，已有业务术语 IRI 不得静默重写 |
| 用 `frozenset` 解包决定关系方向 | 无序集合不表达主客体顺序；显式检查两个方向的 `inverseOf`，不取无序集合第一个元素作为主语 |

`rdf_authoring.py` 是无政策的初次著录工具。其构造函数不能判断业务是否应增加某条公理，模板中的特殊构造也不是每个项目必须包含的清单。
