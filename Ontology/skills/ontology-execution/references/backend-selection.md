# 后端选择与能力声明

后端选择从项目的能力问题与数据条件出发。此参考不强制软件品牌；执行能力必须由具体项目的版本和案例证明。交付要求见 [输出规范](../../../CONTRACT.md)。

工作区已有 [Ontology-tools 本地实现](../../../Ontology-tools/README.md)，版本 `0.3.0`。默认 `local-rules-v1` 提供有限 OWL/RDFS 与 SWRL 固定点、SHACL、SPARQL、独立案例和快照复跑，不提供完整 OWL DL 一致性检查；采用前逐项核对 [精确支持范围](../../../Ontology-tools/PROFILE.md)。其接口可以跨项目复用，领域规则和数据映射仍由项目定义，超出范围的计算或来源接入需要单独适配与验收。

独立 [OWL DL 入口](../../../Ontology-tools/OWL-DL.md)使用随目录保存的 HermiT / OWLAPI，要求本地 Java。`owl-dl` 检查 OWL 2 DL profile、全局一致性和具名类可满足性；`owl-infer` 在通过后导出有限命名分类与事实。两者直接接收明确文件和递归本地导入映射，拒绝 SWRL，不提供逐公理证明、最小冲突解释或所有 OWL 蕴含。

需要 OWL 分类与规则互相触发时，显式选择 [hermit-swrl-projection-v1](../../../Ontology-tools/PROJECTION.md)。它在冻结命名个体和数据值范围内交替运行 HermiT 与受支持 SWRL，每轮重新检查一致性，保存分类、规则前提和逐轮证据，支持统一 `replay`。匿名对象规则匹配、跨析取分支综合、新值和算术仍不在范围内，固定点不得称为完整 OWL DL＋SWRL 完备推理。

规则需要精确四则、显式舍入、时间差或时间偏移并回交 OWL 时，显式选择 [hermit-swrl-calculation-v1](../../../Ontology-tools/CALCULATION.md)。它增加输出变量绑定，仅让成功规则头的新字面值扩张后续候选；命名实体仍冻结。按函数精确 IRI、类型、精度、业务单位和舍入来源验收，并检查生成依赖环与资源预算。日期使用带时区的毫秒时间点，经留证的 UTC 工作视图交给后端；原始输入、规范化映射与实际计算必须可重放。聚合、工作日、新个体及跨析取联合推理仍属缺口。

包执行配置识别扁平契约：`ontology.ttl`、`rules.swrl`、`inputs/facts.ttl` 等，不读取领域包的 `integration/load-plan.ttl`。`local-rules-v1` 拒绝 `owl:imports`，协同配置按各自合同处理包内模型映射。采用 [领域布局](../../../references/domain-organization.md)仍需可重建的适配导出和等价验证；不能只在说明中声称“已合并即可运行”。

大量科学/工程公式可选[结构化公式配置](../../../Ontology-tools/FORMULA.md) `hermit-swrl-formula-v1`：另读静态 `formulas.ttl`，按RDF表达树求值，OWL/SWRL继续处理诊断与适用性。该配置的运算、精度、参数绑定、结果回交和错误状态以专用合同为准；旧 `hermit-swrl-calculation-v1` 仍由原生SWRL维护其业务算式，不能把新能力写成旧配置已升级。

## 各层职责

| 层 | 负责什么 | 不能据此宣称什么 |
|---|---|---|
| RDF / Turtle / RDF/XML | 表示、交换模型与事实 | 文件可解析即能执行业务规则 |
| OWL 推理后端 | 在其支持语义内判断一致性、分类、推导关系等 | 自动执行所有 SWRL 内建、金额计算或工作流 |
| SWRL 后端/受限解释器 | 读取并执行声明支持的规则构造 | 一个受限规则子集等同完整 SWRL 或完整 OWL DL |
| SHACL 校验器 | 对指定数据图检查形状约束 | 输入真实、制度有效、推理结论正确 |
| SPARQL 查询器 | 查询实际加载图或声明的推理视图 | 自动拥有另一个进程尚未保存的推导结果 |
| Neo4j / 属性图存储 | 保存、检索和遍历关系，按实际配置提供查询能力 | 自动替代 SHACL 或提供完整 OWL/SWRL 语义 |
| 大模型 | 理解需求、组织工具调用、解释证据与缺口 | 未运行后端也能声称确定性推理通过 |

## 选择步骤

1. 列出必须回答的能力问题及数据规模/更新方式。
2. 从规则中枚举实际所需的公理、原子、内建、数据类型、聚合和时间语义；同时核对多文件解析、模块依赖、IRI 本地解析及事实加载需求。
3. 选择可获得且符合运行条件的候选后端；依赖、联网和外部连接按用户范围处理。
4. 用最小正向和反例进行能力探针，不先批量迁移再发现能力不匹配。
5. 根据探针和黄金案例决定可执行范围；未覆盖能力保持草案或明确拒绝。

只需离线处理有限事实、复现单个工单和核验规则时，可直接使用本地 RDF 文件与实际推理器。多轮查询涉及持续更新的共享图、多跳关系检索或已有属性图基础设施时，再评估 Neo4j。是否使用数据库由需求决定，不是“本体完整”必须满足的条件，也不设通用数据量阈值。

若采用 Neo4j，额外明确 RDF IRI 到节点/关系/属性的映射、数据类型、重复边、身份合并、更新/删除、来源证据和版本一致性。往返映射或等价性测试证明哪些语义得以保留；不要在 Cypher 内手工维护另一套政策。外部数据库连通性是独立验收项，未连接写 `not_run`。

## README 中的能力声明模板

以下是填写项，不是已有环境或运行结果。

| 项目 | 项目需要填写的内容 |
|---|---|
| 后端身份 | 软件/自研组件、版本、实际可执行入口、依赖文件及获取方式 |
| 输入格式 | 各领域 TBox、规则、ABox、集成入口和形状的实际路径与语法；扁平兼容包或适配导出另列路径 |
| 加载与集成 | 加载计划、实际解析器、声明与实际加载集合、IRI 到包内文件的映射、传递依赖闭包和缺模块行为；集成产物或适配包的重建与等价检查 |
| OWL 范围 | 所支持的语言 profile/公理；profile 检查、全局一致性、具名类可满足性、分类及关系推导分别是否执行；SWRL 是否另行加载 |
| SWRL 范围 | 支持原子、内建精确 IRI、参数/变量绑定、数据类型、递归及终止限制 |
| 计算范围 | 精度、算术、聚合、日期与舍入的实际实现或缺口 |
| 应用语义 | 缺失、冲突、无匹配、人工状态及其依据 |
| 图和校验顺序 | 原始图、闭包图、SHACL 目标、前后置校验、查询读哪个图 |
| 资源与网络 | 本地可用依赖、超时/容量限制、是否允许 imports / SERVICE / 外部连接 |
| 结果及错误 | 输出文件、退出码与结构化状态、证据能力、未支持表达如何拒绝 |
| 数据库选择 | 未采用的原因，或采用时的连接范围、映射和一致性验证 |

字段写“支持”时，附对应测试和执行证据。不能把“能导入 Python 包”“Java 可运行”“发现若干类”当成支持证明。

## 最小能力探针

| 声称的能力 | 最小验证 |
|---|---|
| 类层次推导 | 只提供子类实例，验证上位类型可回答且不在原始图中 |
| 关系推导 | 提供必要边，验证目标逆关系/传递关系或属性链输出 |
| SWRL 比较 | 正向满足、反向不满足和边界相等三例；证明规则被读取并执行 |
| 十进制运算 | 使用可辨别浮点误差的精确预期；金额单位和舍入另按来源验收 |
| SHACL | 故意缺必填字段产生违规，并验证目标节点数量非零 |
| 推导后查询 | 查询输入明确包括本次推导图，命中原始图中不存在的结论 |
| 不支持表达处理 | 加入声明外构造后明确拒绝或标记未执行，不能静默剥离 |
| 领域模块加载 | 对实际采用的加载路径核对 TBox/规则/ABox；漏规则、漏事实或缺依赖时明确失败；有跨域依赖时用联合推导证明相关模块实际参与 |

原生文件可经可追溯、可重建且经过等价验证的适配层交给后端。适配层不是第二套手工政策；不生成 JSON 中间规则。若为单独验证 OWL 子集而排除 SWRL，必须显式标记 SWRL 未执行，不能将整包宣称通过。

模板中的 Python 前向链只能作为待审查的代码材料；把相同业务规则在代码里重写一遍不能证明原生 SWRL 已被解析或执行。使用自研解释器时，须直接读取原生规则，明确支持子集、变量/类型/固定点与拒绝行为，并以独立预期验证。引擎名称也不能替代能力证明：结构遍历检查不等于完整逻辑一致性，具体 OWL/SWRL 能力按实际版本及探针记录。

`merged_ontology.owl` 可以是生成的模型与规则合并图，也可以采用项目明确声明的本地导入入口；两者须分别说明读取方式。前者核对源图并集与集成图，后者核对离线导入闭包与期望源集合。两者都需另外核对本次 ABox，不能依靠入口名称推定规则和实例已被加载。离线依赖缺失时不联网兜底。
