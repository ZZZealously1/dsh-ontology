# 执行命令与证据

按 [输出规范](../../../CONTRACT.md) 保存本次证据。此文件给出方法和填充模板，不包含已执行命令或本次验收结果。

## 先建立实际命令表

从项目包的 README、入口帮助和实际实现核对下表；不能假设 `run` / `check` / `test` 子命令通用。模板中的占位符必须替换为已验证存在的路径或参数，才能成为交付命令。

| 操作 | 记录项 |
|---|---|
| 环境检查 | 所用可执行文件、版本获取命令、必需依赖及版本 |
| 包校验 | 清单核对入口、包路径、路径越界和额外文件检查；加载计划采用的词汇与解析范围 |
| 构建/适配 | 从声明的领域 TBox 与规则重建集成图或执行包的实际命令、源文件集合、比较图的范围和等价检查 |
| 模型/规则检查 | 格式、支持范围检查入口及模型路径；实际加载清单、IRI 本地映射和依赖闭包 |
| OWL DL 检查 | 真实检查器、版本/profile、TBox/ABox 集合与本地导入映射；全局一致性、具名不可满足类、错误/超时状态及报告 |
| OWL 投影/协同 | 冻结命名实体与实际数据候选范围、分类/事实输出、逐轮输入和一致性检查；投影遗漏与非完整联合语义边界 |
| 计算协同（适用时） | 函数 IRI／版本、输入输出及类型、舍入／时间合同、成功规则头新值、初始与逐轮候选、预算、时间规范化及原始／工作视图；见[计算合同](../../../Ontology-tools/CALCULATION.md) |
| 输入校验 | 事实与形状路径、推理选项、报告路径 |
| 推理 | 后端入口、模型/规则/事实参数、结果路径、超时配置 |
| 查询 | 查询器入口、输入图清单、查询文件、结果格式 |
| 黄金案例 | 实际测试入口、案例文件、报告目录、预期比较方式 |
| 快照重放 | 原运行与新运行位置、输入/运行器/依赖指纹核验、对应语义状态及图结果比较 |

若入口是 Python 脚本，PowerShell 调用可以按下列形态记录。它仅示范引用方式，不代表提供了这些文件或参数。

```powershell
# 以下路径和参数均为占位项；先从项目真实 README / --help 核对。
$projectPython = 'C:\实际环境\python.exe'
$projectEntry = 'D:\实际项目\ontology\runtime\实际入口.py'
$projectArguments = @('已确认的子命令', '实际包路径', '实际输入参数')
& $projectPython -B -X utf8 $projectEntry @projectArguments
$executionExitCode = $LASTEXITCODE
```

其他后端使用其真实入口。不要为统一命令而创建空壳脚本或将不存在的历史工具写成依赖。完整命令应可复制重跑，但不包含令牌、密码或连接密钥。

## 本次运行目录

为每次运行使用新目录，放在冻结包外；在 `acceptance.md` 中引用它。可按实际后端调整文件名，README 要说明读取方式。

```text
运行证据/<本次运行标识>/
├── input.ttl             # 实际被执行的事实快照
├── result.ttl            # 派生事实或明确决策状态
├── shacl-report.ttl      # 真实约束校验结果
├── execution.ttl         # 命令、时间、版本、退出状态、指纹
├── report.md             # 业务结果、依据、范围和未决项
├── logs/*.txt            # 实际 stdout / stderr
└── queries/              # 如执行查询，保存 .rq 与 TSV/CSV/Turtle 结果
```

黄金测试另保存 `test-report.ttl` / `test-report.md`，列实际与预期、数量、规则/公理覆盖及未覆盖项。不生成 JSON，也不把 JSON 内容嵌入 Turtle 或更改扩展名保存。

使用领域包时还须保存本次加载计划、解析后的文件清单及源/集成/适配图比较报告。记录每个文件的领域、TBox/规则/ABox 角色、版本、语法、路径与 SHA256，以及导入 IRI 实际解析到的本地文件；说明是否遍历传递依赖、如何处理未知清单项、缺文件及越界路径。`manifest.sha256` 证明文件集完整，不能替代加载计划的语义检查；计划本身也不能替代后端实际加载日志。

比较集成图时按已声明的源集合并集执行 RDF 图同构核对，保留不同源文件中空白节点的作用域；若构建确实进行语义改写，另外记录变换与独立等价验证，不能用三元组数量相等冒充等价。集成头部等非业务元数据的比较排除项应事先明确，不能随结果删去规则或公理。ABox 以本次独立事实快照核对，避免集成模型中遗留业务数据或运行时遗漏实例。

## 一条结论需要哪些证据

从结论向后链接：本次对象与时间 → 结论/状态 → 命中的规则或公理 → 本次用到的输入断言 → 映射转换 → 原始来源定位。规则依据与事实依据分别记录。

报告至少能回答：输入了什么，哪个模型与程序版本作出判断，使用了哪些条件，哪里可以复核。若后端不提供证明轨迹，必须说明证据只到“已验证输入与输出”，不能由大模型补造逐步证明。可以提供基于规则的解释，但明确它与后端生成的证明记录的区别。

采用 HermiT 命名投影或协同配置时，`classification.ttl` 和 `candidates.ttl` 说明输出及候选范围，`rounds/` 保存实际交互。SWRL 结论记录规则和直接前提；HermiT 结论只关联对应轮次与输入快照，不声称逐公理证明或最小冲突集。每轮检查状态独立记录，规则输出导致的矛盾不能被前一轮一致状态覆盖。

字段值和对象关系都应有证据；引用一整个文件不等于定位到某一条值。关联关系来自业务键连接时，记录使用的键、匹配范围和异常处理。

## 执行记录最少信息

| 类别 | 记录内容 |
|---|---|
| 身份与时间 | 运行标识、开始/结束 UTC 时间、执行环境 |
| 输入与模型 | 文件实际路径、版本、SHA256、数据范围和 synthetic/provided 状态 |
| 领域与加载 | 领域及依赖版本、预期/实际 TBox/规则/ABox 集合、加载计划解析器、离线 IRI 解析、源与集成/适配图比较范围及结果 |
| 程序与命令 | 入口/依赖版本、程序指纹、参数、工作目录、实际退出码 |
| 阶段结果 | 解析、OWL、SWRL、SHACL、查询各自结果与日志位置 |
| 输出 | 结果文件、图/结果数量、输出 SHA256、规则/公理依据 |
| 限制 | 缺数据、未支持表达、人工状态、未运行项及其影响 |

RDF 标识和自定义记录属性遵循项目已声明的命名空间，不临时混用多个元数据词汇。文件 SHA256 用于字节一致性，不应被描述为 RDF 语义等价证明。

## 验收结论模板

```markdown
本次状态：<通过 / 部分通过 / 未通过 / 未执行>
实际后端与版本：<真实值>
模型、输入与程序指纹：<证据文件位置>
执行命令及日志：<实际位置>

| 检查 | 状态 | 证据 / 缺口 |
|---|---|---|
| 来源和规格 | <实际状态> | <定位> |
| RDF / SWRL 解析 | <实际状态> | <定位> |
| 领域集成与加载 | <实际状态或不适用理由> | <源/集成图核对、依赖闭包、TBox/规则/ABox 实际清单> |
| OWL DL profile / 全局一致性 / 具名类可满足性 | <三项实际状态或 not_run> | <加载范围、真实后端、全局布尔值、不可满足类清单或执行失败原因> |
| SHACL | <实际状态> | <目标数、违规数、报告> |
| 实际规则推理 | <实际状态或 not_run> | <非空推导与规则依据> |
| 黄金案例 | <通过数/总数> | <独立预期、未通过案例> |
| 覆盖 | <覆盖数/总数> | <未覆盖规则或公理> |
| 外部联调 | <实际状态或 not_run> | <授权范围与证据> |

仍需人工处理：<已确认事项及未解决口径>
可用于哪些问题：<经验证范围>
不能支持哪些结论：<具体缺口>
```

纯查询项目以查询预期替换非适用的推理检查，并写明原因。不要将零对象、零规则命中或零形状目标的运行当作非空推理验收通过。测试预期为“未知/拒绝/人工”的案例通过，表明状态处理正确，不表明业务已自动完成。

## 失败与重跑

保存实际 stderr、退出码、问题文件和失败阶段。修复输入、模型或程序时生成新的运行记录，不覆盖旧报告；更新冻结包时重新生成清单和验收。不能只重写结论页而保留失配指纹，也不能在某一步失败后引用上一次成功输出冒充本次结果。

统一重放可复核实际完成的 OWL 不符合结论，但“重放通过”只表示相同输入和环境复现了状态，不改变本体验收结论。技术失败不算成功推理重放；环境或程序版本改变时保留不匹配结果，另开的新版本检查不能称作旧环境复现。
