# 本体包执行

适用于已有模型的试运行、智能体调用和验收复跑。先按[质量技能](../ontology-validation/SKILL.md)确定要验证的层级，按[规则设计与测试](../ontology-inference-design/references/rule-design-and-tests.md)核对规则的预期含义；模型设计遵循[建模原则](../../references/modeling-principles.md)。

本模块落实[建模流程](../ontology-builder/SKILL.md)的文档路线阶段 8–9，或知识库路线阶段 5，提供后端选择、真实命令、输入快照与复跑证据；不按某个运行器的能力重新定义业务语义。

执行时读取项目包 `README.md`、运行期 `SKILL.md` 及 [输出规范](../../CONTRACT.md)，再读 [后端选择与能力声明](references/backend-selection.md) 和 [执行证据](references/execution-evidence.md)。可用的独立本地实现见 [Ontology-tools](../../Ontology-tools/SKILL.md)；它只是候选后端。采用模板或历史脚本前核对实际能力，不假定参考命令已经可运行。

## 执行前判断

明确用户要的是模型解释、离线校验、实际推理、查询，还是业务动作。大模型可解释模型并组织事实，但只有实际后端完成且保存证据，才能报告“执行了推理”。执行推理不自动授权查库、上传报告、发消息、退费或修改外部系统。

读取包中声明的入口、依赖、版本/profile、支持的语义、输出位置及退出码；默认领域布局还要读取 `integration/load-plan.ttl`，核对领域 TBox、规则、ABox 与集成入口的角色、格式和实际路径。加载契约见 [领域组织](../../references/domain-organization.md)。核对文件真实存在，必要时查看实际入口的帮助或实现。加载计划只是契约，不证明运行器已实现它；没有入口或运行环境时，保留模型并报告该部分 `not_run`，不编造 `python ontology.py run ...` 等命令。

使用 `Ontology-tools` 时先比对其 [PROFILE](../../Ontology-tools/PROFILE.md)。原有接口提供包检查、校验、推导、查询、案例与复跑能力；项目仍提供自己的语义文件和预期。查询本次推导使用保存的 `closure.ttl`，复现使用运行快照和 `replay`，不重新查询源系统充当相同输入。

`Ontology-tools` 的 `local-rules-v1` 规则执行接口仍使用 `ontology.ttl`、`rules.swrl`、`inputs/facts.ttl` 的扁平入口，拒绝 `owl:imports`，不会自动读取新领域布局或加载计划。采用它的领域包须提供实际实现并验证过的适配导出，生成符合该工具契约的独立执行包；源到导出图的等价性、来源关系和重建命令必须可核对。也可选择已支持该加载方式的其他后端，不把目录迁移误报为运行能力升级。

独立的 [`owl-dl` 检查入口](../../Ontology-tools/OWL-DL.md)使用 HermiT，直接加载显式选择的多个原生 TBox 与 ABox，并支持固定的本地递归导入映射；它不解释加载计划、不执行 SWRL、不改变上述规则接口。默认检查纯模型源，含 SWRL 的合并图必须另行选择输入范围，不静默剥离规则。

## 验证任务中的执行顺序

| 阶段 | 动作 | 可交付证据 |
|---|---|---|
| 1. 包与范围 | 核对冻结清单、加载计划、来源版本、能力问题、实际入口和权限范围 | 文件指纹、版本、依赖解析范围、未决事项 |
| 2. 载入模型 | 按明确格式载入声明的 TBox、规则、形状和映射，核对集成或适配结果及支持范围 | 实际加载清单、源与集成图比较、解析报告、能力探针、拒绝项 |
| 3. 准备事实 | 按映射建立身份、属性和关系，逐项载入本次 ABox，保留字段及关系来源 | 本次 `input.ttl`、ABox 清单、数据范围和完整性说明 |
| 4. 语义与输入检查 | 对所选 TBox/ABox 实际执行 OWL DL 全局一致性与具名类可满足性检查，并执行项目声明的前置 SHACL | OWL profile、全局结论、不可满足类与真实后端；SHACL 另存报告、目标数量及违规详情 |
| 5. 实际推导 | 调用声明后端，保留 OWL 与 SWRL 的实际执行范围 | 推导图/决策结果、规则或公理依据、日志 |
| 6. 查询与复核 | 查询指定原始/推导图，必要时做输出约束检查 | 查询文件、结果、图指纹和证据链 |
| 7. 记录结果 | 比较独立预期，归并业务状态和人工项 | RDF/Markdown 运行报告及验收结论 |

这是验证或规则测试阶段内部的执行依赖，不要求每个任务无条件使用所有技术。若形状目标依赖推断类型，应在第 4 步前完成已声明的必要类型闭包并记录，或分开前后两次检查；不能以“后面会推理”为由忽略输入错误。纯查询任务不虚构推理步骤。

TBox 表达类和属性语义，ABox 表达个体断言。ABox 可以包含业务明细、快照或引用，具体粒度由能力问题和数据规模决定；不能把“实例数”冒充原系统行数，也不一概禁止业务明细实例化。

默认集成文件仅由 TBox 与规则源生成，不混入动态业务 ABox，也不手改其内容；事实须作为本次输入显式加载。若项目声明 `owl:imports` 入口，先验证全部传递依赖能按固定 IRI/版本映射到包内文件，解析不越界、不回退联网；缺失模块或无法解析的依赖应使相关执行失败，不能跳过后继续宣称整包通过。以实际加载日志核对预期 TBox、规则与 ABox，不能只检查目录或声明中的数量。

OWL 全局一致与所有具名类可满足是两个检查结果。`owl-dl` 对全局不一致或具名不可满足类返回 `1`；执行失败返回 `2`，不输出有效一致性结论。`owl-infer` 在检查通过后导出命名分类与候选事实；两者拒绝直接执行 SWRL。读取报告与实际退出状态后再判断，不把超时解释成“没有矛盾”。缺后端的检查标记 `not_run` / `blocked`。

需要 OWL 分类与 SWRL 互相触发时，按[协同契约](../../Ontology-tools/PROJECTION.md)显式选择 `hermit-swrl-projection-v1`。保存候选范围及每轮证据，确保规则事实进入下一轮 OWL 检查；匿名存在见证不命名，缺失不当作否定，固定点不代表完整联合语义。状态通过后查询本次 `closure.ttl`，不把失败轮次的诊断图作为有效结论。

算术或基础日期计算参与后续规则和 OWL 时，按[计算合同](../../Ontology-tools/CALCULATION.md)选择 `hermit-swrl-calculation-v1`，旧配置不自动升级。核对函数、类型、业务精度与舍入来源，以及新值候选、依赖环和执行预算。读取 `computations.ttl`、初始／逐轮候选和 `temporal-normalization.ttl`；前置 SHACL 检查原始图，后端及后置检查使用明确的 UTC 时间工作视图。适配与计算都留证，不让大模型自行计算后充当规则输出。

采用静态RDF表达树公式时，按[结构化公式合同](../../Ontology-tools/FORMULA.md)显式选择 `hermit-swrl-formula-v1`，检查扁平 `formulas.ttl` 与领域公式源的图等价。先登记本次请求及完整依赖所需的评估对象，核对同对象/同工况参数和全部必要条件，再运行推理与求值交互。目录候选不能自动成为激活公式；缺参、条件未知、不适用、冲突和数值失败分别报告。只将完整成功结果交给下一轮推理，保留表达树、原LaTeX、绑定、单位转换、计算步骤、精度与依赖证据，并按实际合同重放。旧计算配置及其时间适配行为不因此改变。

UTC 适配保持时间点值，不保证词法约束等价。来源时间格式的正则或长度检查放前置阶段或独立来源字段；后置形状和 `STR()` 查询读取规范化写法，不放宽约束掩盖失败。元数据须按属性角色声明，不凭 Dublin Core 等命名空间跳过数据检查。

统一 `replay` 可从快照复核有限规则、独立 OWL DL 与协同运行，并核对代码、依赖和语义状态；实际完成的 OWL 不符合结论也可复现。技术失败不记为成功重放，版本不匹配不绕过核验。SWRL 依据到直接前提，HermiT 依据到实际轮次及输入快照，不由大模型补造逐公理证明。

## 技术失败与业务状态

模型无法解析、能力不支持、环境缺失、关键输入违规或后端异常时，停止依赖该结果的判断，保存错误并修复后重跑。仍可完成不依赖失败项的来源核对、设计和说明。错误记录不得改写成通过。

无匹配、未知、冲突、人工复核可能是引擎正常运行后得到的业务状态，按项目约定呈现。不要套用其他工具的固定退出码：以当前入口的真实定义为准，同时读取结构化状态。没有推导结果时，说明是零个待处理对象、条件不成立还是缺失能力。

## 智能体职责

- 从已提供材料整理事实及证据，按映射转换；未知值不补造，数据抽取推测不直接当作事实。
- 选择已声明能力内的实际入口，保存命令与版本；缺少依赖时在项目虚拟环境中使用已有离线安装材料，遵守本次授权范围。没有可用本地依赖则记录缺项，不在本任务中联网安装。
- 读取后端的结论、状态、命中规则、公理和输入证据，用业务语言解释；不另写一套语言政策覆盖结果。
- 对冲突、来源失效及已确认人工事项显式保留。记录“需人工处理”不表示已经移交、批准或执行业务动作。

## 结束时交付

按 [执行证据参考](references/execution-evidence.md) 输出本次状态、实际运行范围、命令、结果和缺口。报告分别列出解析、OWL、SWRL、SHACL、查询及外部联调；未做的环节写 `not_run` 或说明不适用。通过的 SHACL 不能替代规则推理和黄金案例验收。
