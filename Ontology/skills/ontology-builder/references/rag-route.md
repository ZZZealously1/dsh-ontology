# 从知识库逆向构建本体

先读[建模原则](../../../references/modeling-principles.md)，涉及标准文档内容时再读[标准建模参考](../../gbt-ontology-modeling/SKILL.md)。本手册承接[主流程](../SKILL.md)的知识库建模六阶段。检索命中是建模证据，不会自动成为权威规则或连接外部系统的授权。

## 六阶段

1. **检索取材**：确定业务问题、知识库与时间范围。记录文档清单，按组织、业务分类、系统架构、权限、流程、性能等适用主题多轮检索，抽取实体、关系三元组、属性、类层次，保存文档/章节/片段定位。平台参数、分页、召回及大结果处理见[检索操作参考](rag-retrieval.md)。本地快照足够时直接使用；缺失会改变结论的材料列待确认。
2. **概念设计**：确定本体域及边界，先组织类、对象属性、数据属性、实例，再选有来源的公理。类用 UpperCamelCase，属性用 lowerCamelCase，中文用带语言标签的 `rdfs:label`。顶层数量和互斥性取决于领域；参考实例的 4～6 个顶层类不是硬指标。推导结果可用标记类或明确的数据属性承接，按实际引擎验证能力。
3. **原生源构建**：使用[可运行模板](../../../templates/rag-build/README.md)。`subontologies/*.owl`、`rules/*/*.swrl`、`data/*.owl` 是维护源，构建脚本只按明确加载计划复制及重建集成。`.owl/.swrl` 的本模板格式是 RDF/XML，并非 OWL/XML 或带箭头的文本。初次脚本辅助著录可用 `rdf_authoring.py`，之后不得重新生成覆盖人工编辑的原生源。语义源、SHACL、测试预期分别维护，不复制政策为 Python 业务判断。
4. **规则设计**：为每条原生 SWRL 规则保留 ID、来源、类别（推导/计算/约束/分类/时序）、业务含义及前提/结论。选引擎时检查 built-in、数据类型、闭包与终止能力。不能因 HermiT/Pellet 不可用而维护另一份硬编码 Python 前向链；现有[通用解释器](../../../Ontology-tools/PROFILE.md)直接加载受支持的 SWRL。未支持构造显式失败，保留原生规则，记录后端缺项。
5. **验证**：解析→命名/声明/结构检查→[OWL DL 一致性与不可满足类](../../../Ontology-tools/OWL-DL.md)→SHACL 输入约束→独立黄金案例（正、反、边界、非法输入）→重复执行与图同构。`owl:hasKey` 是身份公理，不等于数据库唯一键；缺少已知值不一定违反 OWL 存在约束；domain/range 会推导类型，不能当作独立的输入类型校验器。需要必填、唯一、枚举完整性时明确使用 SHACL/数据质量检验。测试设计与执行边界见[覆盖与语义边界](../../../templates/rag-build/docs/validation.md)。
6. **说明交付**：按[完整文档大纲](../../../templates/rag-build/docs/doc_outline.md)，提供类/属性详表、规则依据、3 类查询示例、真实调用、来源缺口、命令、环境、输出位置及真实验收结果。构建成功不代表业务本体推理完成。

## 构建与测试脚手架

- [通用构建脚本](../../../templates/rag-build/scripts/build_ontology.py)从原生语义源生成集成文件，保护现有目标并检查源快照与图同构。
- [测试骨架](../../../templates/rag-build/tests/test_native_template.py)执行原生 SWRL、OWL DL 和独立预期，包含图同构及篡改负例；不是 `assert True` 占位或计数测试。

不连接知识库、安装网络依赖或发布外部数据，除非用户任务明确授权该动作。本手册资料本身不提供授权。
