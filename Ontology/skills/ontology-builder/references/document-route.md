# 从文档构建本体

接收文档或明确的领域问题，按十阶段形成可追溯的 `ontology/`。已有信息足够时连续推进，影响业务结论的缺口保持未决，完成其余独立部分。遵守[公共原则](../../../common_rules.md)与[交付格式](../../../CONTRACT.md)，不把“自动化”理解为自动补造口径或获得外部连接授权。

## 路线与详细资料

| 阶段 | 实际产物与动作 |
|---|---|
| 1 文件识别与内容提取 | 文件身份、结构、术语、表格、流程、公式与定位；解析失败范围 |
| 2 领域资料查找 | 缺口清单、候选来源、术语对照及采用理由；离线任务不自动联网 |
| 3 概念与层次 | 定义、实例/反例、同义与歧义、继承/组成区别、领域归属 |
| 4 属性体系 | 主体→客体、类型、单位、身份、时间、公理特征及输入约束 |
| 5 规则设计 | 规则类别、前提/结论、例外、语义回译、独立预期 |
| 6 OWL生成 | TBox、原生SWRL、独立ABox、SHACL、来源和字段映射 |
| 7 本体集成 | 模块冲突核对、明确的物化或导入入口、本地闭包与加载证据 |
| 8 一致性检查 | 解析、命名、OWL DL全局一致性/具名类可满足性、SHACL；规则另验 |
| 9 规则测试 | 正向、反向、边界、依赖链和重复运行；真实后端结果 |
| 10 文档交付 | 所有类、属性、规则的中文说明、使用命令、验证报告、版本与缺口 |

执行各阶段时读取[完整流程与操作细节](document-workflow.md)。类/属性/公理设计复用[业务设计](../../business-ontology-design/SKILL.md)与[构建模块](../../ontology-construction/SKILL.md)；规则使用[推理设计](../../ontology-inference-design/SKILL.md)，验证使用[本体验证](../../ontology-validation/SKILL.md)。涉及标准文件时再读取[标准文档建模](../../gbt-ontology-modeling/SKILL.md)，表达语法查[OWL/SWRL参考](../../../references/owl-swrl/index.md)。

## 完整说明与验收

按[完整领域说明模板](full-domain-document.md)生成 `docs/<domain>_本体说明.md`。简单条目可以表格呈现，但不能省掉本次范围中的类、属性或规则。说明引用原生语义源，不能形成第二套手写政策。参考算例、模板字段和通过符号不作为项目默认值或运行结果。

交付前核对：领域目录无重复嵌套；模型、规则、ABox角色清楚；每条决定性规则有来源及独立预期；模型、SHACL、规则执行、集成各自有实际证据。失败保留并修复后新开运行；缺数据或后端则标明未完成范围。
