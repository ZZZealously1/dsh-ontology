# 分层验收清单

本清单将语法验证、语义一致性、规则正确性、推理验证和集成验证落实为可检查的证据，按[输出规范](../../../CONTRACT.md)保存结果。它描述要证明什么，不预设执行器、图数据库或项目命令。记录实际运行情况；空输出、缺工具和未接系统不能写成通过。

## 验收前固定范围

在执行前记录包与来源版本、能力问题、模型和输入指纹、后端及支持范围、校验图、测试集与独立预期。原始材料、合成样例、测试事实和真实业务快照分别标记。判断某层不适用时给出理由；所需能力暂时无法检查应为 `not_run`，不能改成不适用。

## 五层验证与配套检查

语法层检查文件和规则结构；语义层检查 OWL 一致性与预期含义，并核对 SHACL 对实际数据图的约束；规则层检查条款回译、原子结构和独立单元测试；推理层用真实后端验证公理、规则、查询及业务黄金案例；集成层检查模块装配、依赖闭包、实际加载与联合行为。以下表格进一步列出各层的证据和来源、文档等配套检查，状态分别记录，不相互替代。

| 层 | 主要检查 | 最低证据 | 不能由本层推定 |
|---|---|---|---|
| 来源与规格 | 标题/版本/定位、有效范围、权威性、冲突基线、阈值与例外依据、决定性缺口 | 来源台账、条款—模型—规则对应关系、确认记录 | 来源权威或政策有效已被正式批准 |
| 语法与结构 | Turtle/RDF/XML 可解析，IRI/词汇/引用正确，SWRL body/head 合法，文件契约及清单完整 | 解析结果、格式检查、清单校验、后端支持项检查 | RDF 解析器已经完成 OWL 语义或 SWRL 执行 |
| 领域集成与加载 | 领域归属、共享词汇与身份、规则依赖；源与集成/适配图核对；加载计划解析范围、IRI 本地映射及传递依赖；实际 TBox/规则/ABox 无遗漏 | 源与生成物指纹、重建命令、图比较报告、加载计划与实际日志、缺模块反例 | 目录名或 import 声明代表已加载全部模型、规则和事实，或图并集已完成语义对齐 |
| OWL 语义 | 所选语义/profile 下的全局一致性、类可满足性、等价/互斥/身份影响与预期蕴含 | 实际推理器/版本、配置、结论和诊断 | 所有业务输入完整，或所有业务规则已运行 |
| SHACL 数据 | 类型、基数、枚举、范围、身份/复合键、关系对象、时间范围、字段与关系证据 | 被校验图、shape 版本、验证报告及明确的 conforms/severity 处理 | 数据真实、外部记录齐全、所有接口已接通 |
| 规则设计 | 来源与规则回译一致；条件、边界、例外、方向、原子/谓词类型、变量绑定及函数契约；计算规则的公式、量纲、参数域和精度 | 条款—规则—案例关联、差异与缺口、函数支持证据及独立算例 | 形式检查或手算已经执行规则，或计算公式适合所有项目 |
| 实际推理/查询 | 实际加载的原生模型、支持的规则/公理、与能力问题对应的非空推导，或符合独立预期的查询结果；禁止结果未出现、轨迹及证据 | 命令、退出码、结果图、规则/公理路径与独立比对 | 流程外审批或业务动作已完成 |
| 业务验收 | 能力问题得到正确回答，作用域、例外、未知/冲突/人工事项与已确认口径一致 | 独立黄金预期、业务评审记录、逐项差异及未覆盖项 | 模型验收等于组织批准或上线许可 |
| 中文说明与交付 | 所有类、属性和规则具有完整中文说明；领域说明涵盖结构、来源、映射、运行命令、案例和实际验收状态，统计与原生文件一致 | 按[领域说明模板](../../../templates/domain-doc.md)核对说明与 IRI/规则清单、实测统计及文件链接 | 文档描述某能力即证明已实现或已运行 |
| 外部联调 | 授权范围内接口、存储、消息或动作与约定一致，错误响应可追踪 | 实际请求/响应或运行日志、环境与授权范围 | 本地离线验收已经完成真实外部调用 |

本体构建、集成或公理变更后须执行 OWL DL 全局一致性与具名类可满足性检查，可使用 [owl-dl](../../../Ontology-tools/OWL-DL.md) 或经验证的等效后端。按实际加载的 TBox/ABox 留证；SWRL 单独验证。检查器的 `nonconformant` 表示真实完成后发现不一致或具名不可满足类，验收不可标为通过；技术失败、超时、profile 不支持须记录缺口，不推定一致或不一致。

OWL 检查不应把类层次出现环一律判为错误：互相包含可能表达等价，需核对其含义是否符合设计。不可满足类与整个本体不一致分别报告。`domain`、`range`、函数属性和基数公理产生的语义后果，也应与业务意图核对；它们不直接替代输入唯一性与必填检查。

代码样例需实际可用：RDF/XML 解析不等于 OWL/XML 解析；只查询 body/head 不足以验证 SWRL 的 RDF 列表及原子。结构型推理器、手写类遍历或只检查显式类型冲突的脚本，其能力范围不能被报告成完整 OWL DL 一致性检查；涉及继承、等价、互斥和身份推导时验证实际闭包及诊断范围。类环或缺少显式 domain 的提示先核对建模意图，不为消除提示无依据地改模型。

SHACL 应说明使用原始事实图、推导图还是两者合并，并记录推理选项。以 warning/info 为可接受结果时需有明确验收约定，不能静默改变 severity 或跳过 shape 使失败消失。非零退出、加载失败、超时和没有实际执行均不得写成 conforms。

默认领域包的 `integration/merged_ontology.owl` 是 TBox 与规则源的生成产物，动态事实独立放在 ABox。验证生成过程可重建，按声明源集合比较 RDF 图同构并保持空白节点作用域；头部元数据等排除范围须预先说明。若不是图保真合并而是语义转换，须有相应的独立等价验证，不能靠数量或文件名认定等价。不得在集成文件和领域源之间人工双向维护。

集成比较需检查遗漏与无依据新增，不能只比较三元组数量或单向包含关系；跨序列化的空白节点不能直接以标识符做集合差。导入路径使用显式 IRI 映射，不能截取 IRI 尾段猜测文件名。多父类、传递依赖和规则模块都应纳入实际范围，不能用只跟随第一个父类或直接 imports 的脚本代替完整检查。

检查 `integration/load-plan.ttl` 的实际解析实现与支持词汇、路径范围、版本锁定和遗漏处理。采用 `owl:imports` 时，验证离线闭包能固定映射到本地文件，无缺失、越界或联网回退；仅导入 TBox 不等于加载规则或 ABox。`Ontology-tools` 包执行仍检查实际适配导出与扁平契约：`local-rules-v1` 拒绝 imports，协同配置按包内映射加载；各配置均不会因增加领域加载计划而自动解析它。独立 `owl-dl` / `owl-infer` 按显式文件与本地导入映射契约核验。

核对未决规则候选与本次执行集合的隔离。标注 `draft` 或 `inactive` 不证明规则已禁用；应检查实际规则图/加载选择，并用草案不得触发本次业务结论的反例验证。后端不支持启停时，候选应留在非执行记录或独立排除位置，不能依赖被忽略的注释。

## 黄金与反例设计

| 案例类别 | 检验点 | 预期应写明 |
|---|---|---|
| 正向 | 满足全部前提及关系/时间作用域 | 精确对象、推导类型/关系/结果与可追溯依据 |
| 反例 | 分别移除或改变必要条件 | 指定结论不应被推得；如需否定结论，必须另有显式依据 |
| 精确边界 | 等于阈值、阈值两侧、跨周期/生效边界 | `<`、`≤` 等边界语义及时间/单位口径，不自行造容差 |
| 缺失与失败 | 缺字段、空值、接口失败、无业务、false、0 | 分别采用的拒绝、未知或人工处理行为 |
| 冲突与多规则 | 多条规则同时满足、矛盾事实、已定义的优先级 | 冲突或合并结果及其应用语义，不依赖遍历顺序 |
| 身份与关系 | 同名异物、复合键重复、错误关联、跨工单/跨周期 | 拒绝或隔离，不跨对象拼接条件 |
| 模块与跨域（适用时） | 缺 TBox/规则/ABox、未解析的依赖、共享术语冲突、跨域身份连接及规则交互 | 缺必要模块明确失败；在完整加载图上给出独立联合预期，不依赖导入顺序 |
| 数值与集合 | decimal 精度、单位混用、集合缺成员、去重/聚合范围 | 计算或拒绝依据；未确认舍入、尾差等保持缺口 |
| 后端边界 | 不支持的原子、内建函数、算术、递归或外部引用 | 明确拒绝或未支持状态，不能静默省略条件 |
| 证据缺口 | 字段或关系无来源、失效引用、未经核对的合成值 | 可定位的错误或人工项，不把来源引用当真实性证明 |
| 回归 | 历史缺陷、旧模型已确认行为、迁移前后相同输入 | 保留原预期；已授权语义变化单独列差异依据 |

边界案例的具体值由实际阈值与类型决定，不能从测试样例反推政策。负向案例检验的是“不应推导指定结果”；在开放世界语义下，缺少某事实不等于该事实为假。有限案例不能证明全部可能输入，但可证明明确测试范围内的行为。

纯查询任务验证记录集合、对象范围、排序/聚合口径及空结果预期；推理任务至少实际产生一项与能力问题对应的非空分类、关系或决策。只加载文件、检查无错误或获取空列表不足以证明推理能力。

## 防止测试表面通过

- **规则隔离与组合分别验。** 用最小事实验证单条规则的必要条件，再用完整模型验证组合效果。若其他规则仍能合法推出相同结论，不能要求整个模型因一个条件变化而必然失去结论；案例须声明其范围。
- **实际执行与预期计算分开。** 数学函数、手算或已知示例用于独立预期，实际值必须来自目标后端的保存产物。推理占位、空循环、手写结果或直接把预期作为输入，都不能算规则测试。
- **检查全部相关结果。** 对指定对象比较完整目标值集合、数据类型、单位和禁止结果，不能用 `graph.value()` 任取一个值来忽略额外错误结果。需要新增推导时核对运行前后差异。
- **负例先证明执行成功。** 加载失败、超时、后端不支持或未运行都不等于“条件不满足”。负例的空结果须同时有正常完成证据；单调规则的未推得仍不表示事实为假。
- **数值预期确定。** 使用经确认的精确值或容差及其依据，不设默认误差率；不要让“没有值或任意非负值”这样的宽泛断言替代明确预期。参数域错误、单位错配和舍入边界分别测试。
- **修复针对真实原因。** 保留失败图、预期、实际和日志；定位来源、建模、映射、后端或测试错误后修复相应源。不得无依据地放宽约束、删除事实或手动加入结论。

正向规则依赖环不自动等于错误，按实际语义检查收敛、无限数值/个体生成风险及终止状态。时序规则若增加新状态，应检查旧状态保留时的语义与候选/确认状态边界，不把新的断言当成已完成状态覆盖或审批。

采用 [计算配置](../../../Ontology-tools/CALCULATION.md)时，增加以下独立验证：超默认 Decimal 精度的精确算术、除零／无限十进制／显式舍入；输出绑定与规则原子重排；同时间点不同偏移、闰日、毫秒和缺时区；成功规则头新值进入候选、失败分支中间值不进入候选；DL→计算→DL→再计算及新增事实造成矛盾；生成依赖环与预算停止。日期工作视图须保留原始快照和 UTC 映射，后置 SHACL 与规则用同一视图；核对 `computations.ttl`、计算合同、候选、规范化和预算的重放比较。涉及 OWL 的关键测试实际调用 HermiT；语义不符合、SHACL 与计算失败分别设预期。

时间规范化的保真范围是时间点值，另验 `sh:pattern`、长度约束和查询 `STR()` 的词法差异。前置与后置使用的图分别列明，不能修改正则或忽略后置失败。元数据豁免按明确注释属性角色核对，不把整个 Dublin Core 命名空间当作非业务数据。

采用[结构化公式配置](../../../Ontology-tools/FORMULA.md)时，另验静态公式目录的表达树结构/输出方向、源与扁平导出图等价、原式显示、参数绑定与对象/工况范围、单位转换、必要条件及完整依赖。未知条件、缺参、输入冲突、未支持模型与数值失败各有明确预期；不得以大模型求值或失败中间值冒充后端成功结果。实际运行应验证公式结果回交推理、完整中文问题的多轮补数/修正流程，以及合同规定的公式证据重放。

## 覆盖记录

- 质量要求为：所有适用规则有单元测试，实际规则执行覆盖率至少 80%。单元测试设计覆盖与实际执行覆盖分别记录，不能用已写测试替代已执行。该门槛不是业务决策数值或计算容差。
- 规则执行覆盖分母为执行前冻结的全部适用规则 IRI，说明哪些候选、停用规则或非本次范围被排除及理由。规则适用却因工具不支持、缺输入或遗漏加载而未执行，仍须保留在分母和缺口中，不能删去提高比例。公理、条件分支与能力问题另设分母。
- 规则执行覆盖的分子来自实际后端成功执行且与独立正向预期一致的规则 IRI；每项关联案例、加载范围和实际产物。可使用真实轨迹，或范围明确的单规则/独立蕴含测试作为证据，说明其能证明的范围。比例按“已覆盖适用规则数 / 全部适用规则数”计算；没有执行证据不能宣称达到 80%。
- 领域包同时列预期与实际加载的模块及依赖，不能通过缩小加载集合来提高覆盖；跨域能力按实际需求列出，单域无需人为添加。
- 区分“规则被执行/命中”“公理参与预期蕴含”“条件分支”“边界”“能力问题”覆盖。后端没有轨迹时如实说明用独立蕴含测试验证的范围，不伪造命中轨迹。
- 规则 IRI 与案例 ID 建立明确映射，并关联实际执行证据；测试类名、函数名或文件中的文字出现次数不计为已命中。只有负向不触发案例不算正向规则覆盖；规则集合为空时说明不适用范围，不执行除零或虚报百分比。
- 列总量、覆盖量、比例、未覆盖 ID、未执行理由和补测计划。达到 80% 不能豁免已发现的任何失败，也不自动消除未执行范围；未达到门槛或关键能力尚未验证时，不宣称整包验收通过。项目另有明确质量要求时记录来源及与本门槛的关系。
- 覆盖全部规则仍不等于覆盖全部条件组合、跨规则交互或业务流程；未匹配案例通过也不构成任何规则的正向命中。
- 结构化公式以执行前冻结的全部激活公式IRI为分母，逐式关联来源、独立预期、实际求值、单位/条件及结果证据，全部须通过；候选与不支持项另列。公式覆盖与SWRL至少80%的实际规则覆盖分别报告，公式不能替规则计数，算法精度也不能代替公式容差。
