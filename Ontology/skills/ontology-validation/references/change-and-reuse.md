# 变更、迁移与复用

所有操作遵守[输出规范](../../../CONTRACT.md)，保持原生 OWL/SWRL/SHACL 为可追溯语义源，不生成 JSON。复用参考资料、读取源数据与执行外部写入是不同动作；既有建模授权不自动扩展为数据库导入、消息通知或远程发布授权。

## 区分操作性质

| 操作 | 主要变化 | 核对重点 |
|---|---|---|
| 版本升级 | 本体、规则、约束或后端版本变化 | 新旧行为、来源有效期、兼容性及消费者影响 |
| 序列化转换 | 同一 RDF 图在 RDF/XML、Turtle 等格式间转换 | 图结构与字面值保真、空白节点图同构；不凭文件后缀判断语义 |
| 数据迁移 | 旧文件、表或接口事实转换到目标身份与词汇 | 身份、类型、单位、空值、时间、关系、证据和集合完整性 |
| 领域拆分或重组 | 单一模型分域、共享术语归属或模块依赖变化 | 保留稳定 IRI，核对 TBox/规则/ABox 角色、加载计划、源与集成等价及原预期 |
| 本体融合 | 多个模型对齐并形成共同视图或模型 | 概念/实例身份、来源权威、冲突、推导变化与可分离性 |
| 扩展与泛化 | 支持新的概念、数据源、场景或更广适用范围 | 新范围的依据、既有语义是否改变、反例与回归 |

格式迁移不应偷偷改变政策；新字段接入不一定需要新类；更换推理后端即使模型文件未变，也需要检查其支持范围和执行语义。一个任务可能同时涉及多种操作，分别记录。

## 通用变更步骤

1. **固定基线。** 保存原包、来源、事实、独立预期和实际后端指纹；冻结包不就地覆盖。
2. **说明目标。** 记录新能力问题、来源变化、用户已确认的处置、预期行为变化和禁止动作。
3. **分析影响。** 沿领域依赖—类/属性—shape—规则—映射—事实—查询—案例追踪依赖，区分文案、加载结构、数据结构与业务语义变化。
4. **设计转换。** 明确旧新 IRI、键、字段、单位、时间、例外和证据如何对应；无法无损转换时列明损失与人工项。先用代表性样本检查身份碰撞、无法表示的公理和未映射数据，再决定完整转换范围。
5. **在新版本实施。** 生成新的原生文件与必要的转换产物。适配程序可以执行转换，但不能成为第二份手写业务政策。
6. **执行比较与回归。** 先检查输入与模型，再跑分层验收；对照旧预期并单列已获依据的行为变化。
7. **交付差异。** 保存变更记录、映射、失败与复验、实际兼容范围、回退方法和新清单。未实施的切换或外部操作写为未执行。

## 格式转换与数据迁移

先区分“换一种序列化”与“改变模型或数据”。前者要求保持同一图，后者需有明确映射、预期差异和回归，不能统一用记录数或三元组数量作为通过条件。

### 格式转换

1. 识别实际语法和加载边界，固定源文件、所需本地依赖、解析器及版本；不要仅根据 `.owl` 或 `.swrl` 后缀猜测。RDFLib 的 `format="xml"` 指 RDF/XML；OWL/XML 是另一种 OWL 序列化，需要明确支持它的解析/转换工具。
2. 显式指定输入输出语法，写入新位置。保持绝对 IRI、相对 IRI 的解析基准、数据类型、语言标签、规则原子、RDF 列表和匿名结构；若要求字面值词法原样保留，还要单独核对词法形式，不能让解析器的值规范化掩盖变化。
3. 重新解析目标。对于同一 RDF 图的转换，用空白节点无关的图同构比较；命名图数据还须保留图名和每个图的范围，不能先展平再称数据集无损。分别报告缺失内容、意外新增和已声明的元数据变化。
4. 若涉及 OWL/XML 转换、语义重写或推理后端变化，再检查公理/规则保留和独立能力问题；图同构只能证明图级保真，不能单独证明业务含义或后端执行能力。

目标格式仍服从中央规范：新 `.owl` / `.swrl` 为 RDF/XML，`.ttl` 为 Turtle；不生成 JSON/JSON-LD。三元组数量可用于发现异常，数量相同或差异低于某个比例都不能证明语义保留。遇到工具不支持的构造应保留源并报告缺口，不删去构造以换取转换成功。

### 事实与旧模型接入

首先判断输入是概念定义表、业务记录，还是二者混合。定义表经核对后生成 TBox；业务记录按身份与字段契约生成 ABox，不能把每个行值都创建为类。映射继续在 `mapping.ttl` 维护，复用既有源定位和执行实现，不另建 JSON 映射或第二套政策。

- 原始文件保持可追溯。序列化转换比较规范化后的图或图同构关系，不用文本行数、三元组数相等替代语义保真。
- 只有依据明确的业务键才能建立稳定身份；行号或内容哈希可作为临时技术标识，但不能声明其保证跨文件、跨快照的业务同一性。
- 字段名、类型和样本分布用于提出候选映射，不能凭相似度自动确认业务含义；不自造自动采纳阈值。
- 保留原值和转换依据。缺失、空串、接口失败、无业务、false 和 0 分别处理；不把所有缺值统一改成零或直接删除其业务含义。
- 使用映射声明的主键、复合键和关联键，不硬编码列名 `id`；生成 IRI 时采用明确的编码与碰撞检测，缺键、重复键和悬空关系有可检查的处置结果。
- 核对源记录及业务键集合、成功/拒绝/未映射集合、关系端点与字段值；去重、拆分或合并导致数量改变时列出对应关系。按定义的窗口与成员范围验证聚合，不能只比较总数。
- 历史格式转换时保留迁移前预期和来源指纹。无法表示的规则或公理需明确报错或列出损失，不把删去不支持语义后的产物称为等价迁移。

默认使用用户提供的本地导出文件。参考材料中的数据库连接或 SQL 示例不是连接授权；真实接入、写回和切换属于独立任务。迁移在新版本位置完成，保留旧包、转换命令、输入输出指纹、异常记录和回退所需文件。

从旧的 `ontology.ttl` / `rules.swrl` 扁平布局迁移到 [领域布局](../../../references/domain-organization.md) 时，先确认实际业务边界，不以目录名制造新领域。把 TBox、所属规则和 ABox 分别迁入对应位置，原始 IRI 不因移动文件自动改名；如原模型夹带静态参考个体，单独声明其角色和加载位置。核对原图与新源集合的保真程度、身份不变性及旧案例结果，记录确有依据的语义变化。

新增或更新 `integration/load-plan.ttl` 后重建集成产物，默认只合并声明的模型与规则，动态 ABox 按运行范围加载。集成文件不是新的编辑入口；修正回到领域源，再生成、比较和验收。采用 imports 入口时固定传递依赖与本地解析方式，改布局后验证不会遗漏规则或实例。若后端依然只接受扁平文件，保留可复现的导出适配及来源映射，或选择兼容后端；目录迁移本身不等于后端已经迁移。

## 融合与对齐

先判断任务只需将多个模块装配为一个加载视图，还是确需改变概念之间的语义关系；装配方式见[领域组织](../../../references/domain-organization.md#4-集成不等于语义融合)。对后者按“差异盘点—候选对齐—冲突分析—有依据的处理—构建—验证”执行，不能先合并再反向解释结果。

分别盘点输入本体的 IRI、版本、业务范围、类/属性、规则、公理、事实与依赖。标签、同义词和结构相似度用于提出候选；相同标签、得分或默认置信度都不直接产生等价公理。逐项比较定义、成员边界、身份粒度、时间与来源依据，再决定复用、精确对齐、近似映射或保持独立。

候选及决策写入 `mapping.ttl`，来源、冲突与未决依据写入 `provenance.ttl`；记录源/目标 IRI、对象种类、拟用关系、证据、状态和采用理由。已确认的逻辑对齐在明确归属的 TBox 或规则源中实现；候选映射本身不参与等价推理。文档引用这些记录，不平行维护另一份政策。

| 对齐对象 | 可能采用的表达 | 必须先核对 |
|---|---|---|
| 类 | 保持独立、子类关系、`owl:equivalentClass` | 成员含义、定义条件、适用范围是否一致 |
| 属性 | 保持独立、子属性关系、`owl:equivalentProperty`，或有依据的 `owl:inverseOf` | domain/range、单位、方向、时间与空值语义；两端类型对调本身不足以证明互逆 |
| 个体 | 保持独立，证据充分时 `owl:sameAs` | 同一业务对象、粒度、有效期及全部属性可互换的后果 |
| 词汇或业务近似概念 | 明确的映射关系及映射状态 | 近似对应不能误写成严格逻辑等价 |

`owl:sameAs` 表示个体同一性，不用于建立类等价；即使一个 IRI 同时作为类和个体使用，个体同一性也不替代 `owl:equivalentClass`。若只是同工单、相同姓名或相似属性指纹，保留关系或候选映射，不自动合并身份。

差异不全是逻辑矛盾。父类列表不同可能只是一个模型声明了另一个可推得的上位类；先比较定义与蕴含，再判断是否冲突。按下表形成有依据的处理：

| 差异或冲突 | 核对与处理 |
|---|---|
| 同名异义 | 保留各自稳定 IRI，补充标签、定义和范围；必要时用命名空间区分所有权，不为改名而破坏现有引用 |
| 异名同义 | 证明定义和成员范围一致后选择复用或等价公理；只有近似对应时使用明确的映射关系 |
| 层次或定义差异 | 检查继承蕴含、互斥、限制及预期分类；依据支持时选择子类、桥接或共同上位概念，不能自动删掉某方公理 |
| 属性差异 | 比较数据类型、单位、方向、domain/range、基数和时间语义；必要转换由映射承担，不能用字符串化消除类型冲突 |
| 事实或规则冲突 | 保留各方来源；仅按已确认权威、生效期和适用范围选择，证据不足时保留未决或原已确认人工处置 |

“优先源”必须有来源依据，不能默认第一个输入胜出。属性集合的并集也不证明兼容：给同一属性添加多个 `rdfs:domain` 或 `rdfs:range` 会带来同时满足各声明类型的推断，不表示任选一个类型；确需并集或类型替代时显式建模并检查后端支持。引入新概念、保留两套命名空间或添加桥接都要说明业务含义，不能仅靠技术重命名消除冲突。

在源文件上实施已确认处理后再重建集成入口，保持空白节点隔离并保留源到产物的映射。纯装配按预期源图检查同构；有意删改或重写时单列原公理、替代公理、依据与预期差异，不能仍以“原图全部保留”掩盖语义修改。

融合后检查新增蕴含、等价传播、互斥冲突、身份合并、关系范围和规则多重命中。两个模型分别一致，不保证合并后仍一致或业务结果仍符合预期；融合验收必须实际针对合并图。用同一批受控事实比较各源模型与融合后的结果，保留新增/消失的推导和来源；预期应来自能力问题及确认的融合决定，不从合并输出倒填。

验证前说明所称“等价”是图级保真、公理语义关系，还是特定能力问题下的行为保持，并固定后端、比较的对象/蕴含/查询范围与允许差异。有限黄金案例只支持已测行为范围，不能据此宣称已证明一般逻辑等价；需要更强结论时另列证明能力及未完成范围。

把多个文件做 RDF 图并集只证明装配了声明内容，不证明跨域语义已对齐。涉及跨域关系与规则时，分别记录术语所属域、共享定义、身份连接和依赖版本，并用独立联合案例和错误关联反例验证；没有跨域能力需求的单域项目不强制做融合。

## 扩展、泛化与版本

新增命名空间可隔离词汇所有权和版本，但不能自动保证语义兼容。新增字段也需检查已有同名 IRI 是否被重新定义、domain/range 是否影响已有事实、shape 是否增加必填、规则是否改变结果，以及查询和消费者是否接受新结构。仅新增规则、子类、互斥关系或枚举值也可能改变推导、导致冲突或使既有 SHACL 拒绝输入；“只增不改”不能替代兼容性分析。

扩大适用范围时，重新核对边界条件、来源有效性和反例，不将某地区、某账期或某类用户的规则直接推广。旧 IRI 的业务含义改变时优先明确版本或引入新概念，保留旧新对应和弃用说明，不悄悄重定义既有身份。

项目可以采用语义化版本，但版本级别依据实际兼容影响，不依据编辑行数：

- 不改变执行含义的标签、说明或证据定位修正，可以按项目约定作为修订版本。
- 经回归证明兼容的新能力，可以按项目约定作为功能版本。
- 改变输入契约、身份、规则结论、shape 接受范围或既有推导的变化，按不兼容或需迁移的版本处理。

修改 SHACL 不天然属于小修补，新增规则也不天然向后兼容。后端升级记录旧新版本、支持的原子/数据类型及行为差异，并使用同一批独立预期回归。

版本历史可使用项目已采用的 Git 或不可变归档与指纹；本方法不强制提交、改写历史、打标签或推送。正式发布、部署和切换按当前任务的实际授权执行，不能从验收通过推定这些动作已获批准。

## 变更评审模板

```markdown
# 本体变更评审

- 操作类型：升级 / 序列化转换 / 数据迁移 / 领域拆分或重组 / 融合 / 扩展与泛化
- 原版本、目标版本、模型/事实/后端指纹：
- 目标能力问题与来源依据：
- 用户已确认的处理范围、仍待确认事项：

| 变更对象/IRI | 原含义或行为 | 新含义或行为 | 依据 | 影响的规则/shape/映射/案例 |
|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 可定位来源 | 具体 ID |

| 迁移或对齐项 | 对应关系/转换 | 身份与时间范围 | 无损性与冲突 | 验证证据 |
|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 已知损失或人工项 | 实际结果 |

- 候选对齐与已采用对齐、冲突分类、处理依据及未决项的位置：
- 保留的原始资料与旧预期位置：
- 实际输入输出格式、解析基准/工具版本、图同构或声明的语义差异证据：
- 源/目标业务键及成功、拒绝、未映射集合；字段和关系保真证据：
- 领域归属、依赖与加载方式变化；集成/适配重建和源图比较证据：
- 新增推导、消失推导、接受/拒绝输入变化：
- 兼容性结论与独立回归结果：
- 未支持或未执行的环节：
- 新旧包及 manifest.sha256：
- 回退或并存方法及实际实施状态：
- 评审结论和外部动作的独立授权/执行状态：
```

只完成设计时明确写“变更方案”；实际生成和验收后才写已完成的范围。旧版本可恢复不代表已验证回退过程，未演练时如实记录。
