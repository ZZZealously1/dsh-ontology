# 验证与验收

适用于构建完成、发布前检查、模型/规则变更、集成、推理异常及质量审计。本技能贯通意图审查、五层验证、覆盖验收、修复和版本冻结；遵守[公共原则](../../common_rules.md)和[输出规范](../../CONTRACT.md)。先固定实际输入与独立预期，不凭文件存在或人工阅读判断通过。

## 验证与验收流程

1. **核对意图并固定范围。** 按[意图、验收与演进流程](references/acceptance-and-evolution.md)记录请求、来源、模型/规则/事实版本、导入闭包、后端、能力问题及预期交付层级；逐项对应IRI/规则，标明一致、冲突、缺失或证据不足及影响。核对定义、身份粒度、时间口径和行为，同名或单个样例不能证明一致；保留已确认的人工处置。
2. **执行五层验证。** 按[五层验证手册](references/validation-workflow.md)依次执行**语法 → 语义一致性 → 规则正确性 → 推理验证 → 集成验证**。前层失败时停止依赖它的后层，独立检查可继续并保留失败证据；不得修改冻结输入使其通过。
3. **收集证据并审查覆盖。** 按[验收清单](references/acceptance-checklist.md)核对来源、OWL DL、SHACL、规则/查询、实际加载、独立黄金与反例。各层分别留证，比较完整结果集合、类型及禁止结果；规则隔离与组合分别验，负例先证明执行成功。
4. **修复并复验。** 将问题归到来源、建模、映射、后端或案例，保留失败快照。只凭来源依据修正预期，不手补结论、删除冲突事实或放宽约束来迎合引擎；身份、公共公理、优先级或后端变化时扩大必要回归。
5. **限定验收结论。** 用[验收模板](../../templates/acceptance.md)记录真实命令、输入/图范围、日志、结果、独立比对、适用范围、未执行项和人工事项。所有类、属性、规则的中文说明及统计与实际原生文件核对；模型验收、组织批准、上线和业务动作分别记录。
6. **冻结与演进。** 验收后的包用 `manifest.sha256` 覆盖除清单自身外的全部文件，后续运行输出写包外；修改形成新版本并保留旧版及指纹。按[变更与复用](references/change-and-reuse.md)记录语义影响、兼容性、受影响案例和恢复位置；未演练的回退不能报告为已验证。

## 检查与通过口径

- 构建、集成或公理变更后，须使用实际 [HermiT 检查器](../../Ontology-tools/OWL-DL.md)或经验证的等效后端检查OWL DL全局一致性与具名类可满足性，记录实际TBox/ABox及导入范围。SHACL和SWRL使用各自支持范围内的执行器，见[工具入口](../../Ontology-tools/SKILL.md)。选择[有限投影协同](../../Ontology-tools/PROJECTION.md)时验证多轮交互、冻结候选范围和每轮一致性；三类检查不能互相替代，协同固定点不代表完整联合语义。
- 所有适用规则须有单元测试设计，实际规则执行覆盖率至少80%。执行前冻结适用规则IRI分母；成功执行、符合独立正向预期且有实际产物证据的规则计入分子。缺后端、缺输入或漏加载的适用规则不能移出分母。完整统计、无规则情形及未覆盖清单见[覆盖记录](references/acceptance-checklist.md#覆盖记录)。
- 覆盖率不能豁免任何失败，也不能代替反例、边界、组合、公理及能力问题验证。跨域项目验证联合行为与错误关联，单域不为凑案例增加跨域依赖。
- 保留后端原始状态并按其契约解释：例如OWL DL的 `nonconformant` 是检查完成但不符合，`failed` 是技术执行失败，不能将此映射套到所有后端。`not_run`、有依据的不适用与依赖阻塞分别说明；真实不一致、规则失败、结果不符或断裂依赖不能交付为已通过。
- 缺后端或只做文档审查时，结论限定到实际已验证范围，不宣布推理完成。推理任务须有真实非空推导证据，纯查询按其预期结果与口径验收。
- 黄金预期分别表达 SHACL 不符合、OWL 全局不一致、具名类不可满足及指定阶段技术失败；不要用任意异常满足同一“非法”预期。重放核对输入、依赖、代码、语义状态和图结果；复现一个不符合结论不能当作本体通过，技术失败和跳过关键语义测试不计为验收成功。
- 采用[计算协同](../../Ontology-tools/CALCULATION.md)时，独立验证精确数值与舍入、绑定与原子重排、带时区同值／日期边界、新值触发 DL、生成依赖环和预算停止。核对初始与逐轮候选、计算轨迹、时间规范化与原始输入；未命中分支的中间值不能扩张候选。实际调用 HermiT 验证时间适配与计算后的分类／矛盾，再验证快照重放及篡改拒绝。
- 采用[结构化公式配置](../../Ontology-tools/FORMULA.md)时，单独核验静态目录与导出图、表达树、原式显示、同对象/工况绑定、单位与参数域、必要条件、完整依赖和资源预算。每个激活公式均须有独立算例并通过，公式覆盖单列；失败和不适用不能以语言计算替代。验证完整成功结果回交后产生推导、错误中间值不泄漏、中文问题到追问/求值/解释的完整流程及快照重放。

语义融合使用[融合技能](../ontology-fusion/SKILL.md)，格式、版本或数据迁移使用[迁移技能](../ontology-migration/SKILL.md)；本技能负责相关变更的验证与验收。
