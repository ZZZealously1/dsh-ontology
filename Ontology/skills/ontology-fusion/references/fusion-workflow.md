# 融合、对齐与冲突处理

## 输入分析与模式选择

记录每份本体的IRI、版本、命名空间、领域边界、类/属性/规则数量、ABox范围、来源权威和传递依赖。先问需要哪个能力问题：并排查询、统一加载、共享概念、跨域推导还是身份归并。纯图并集不意味着已语义融合；imports入口不是物化合并。共同约束见[领域组织](../../../references/domain-organization.md)。

## 候选对齐

原标签匹配方法保留为**候选发现**，同时保留同一标签的所有实体、所有语言标签，不用字典覆盖一对多。标签缺失、不同语言、大小写/缩写、同义词可形成另行核对的候选；精确命中不赋置信度1.0，相似结构不默认0.8。属性结构比较保留定义、父类、domain/range、限制、单位、方向、基数和时态证据；本脚本不实现无验证依据的语义相似评分。

在 `Ontology` 为工作目录：

```powershell
python -B -X utf8 skills/ontology-fusion/scripts/fuse_local.py candidates --left <本地模型A> --right <本地模型B> --output <新候选目录>
```

脚本按实体种类、完整标签字面值（含语言/类型）匹配，并记录具名父类/domain/range签名；匿名限制仍在原始快照核对，候选报告不声称提取了完整定义。输出 `result.ttl` 为候选，不含自动等价公理。候选适用于已有明确实体声明的类、对象属性、数据属性和具名个体；遗漏未声明/无标签实体不意味着不存在对齐。

正式映射写入项目 `mapping.ttl`，字段至少包括源/目标IRI、对象类型、拟用关系、证据、状态、采用理由、范围和版本。核对概念定义、成员边界、身份粒度、有效期；只有证据足够才确认逻辑等价。`owl:equivalentClass`用于类，`owl:equivalentProperty`用于属性，`owl:sameAs`仅表示个体身份，不用来合并类；近似概念使用明确业务映射而非强逻辑等价。

本地辅助工具接受的已审桥接格式（工具自有词汇，不宣称标准对齐协议）：

```turtle
@prefix f: <urn:ontology:local-fusion:> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .
[] a f:Alignment ;
  f:source <urn:example:a:Component> ; f:target <urn:example:b:Part> ;
  f:relation owl:equivalentClass ; f:status "approved" ;
  f:evidence <urn:example:review:definition-comparison> ;
  f:reason "合成示例：已独立核对定义与成员边界一致" .
```

`approved`只表示输入映射已获使用者确认的语义决策，不是工具审批业务。例子本身不授权真实对齐。所有条目必须已审且有理由/证据；未决与候选另存，不混入待应用映射。脚本支持 `equivalentClass`、`subClassOf`、`equivalentProperty`、`subPropertyOf`、`inverseOf`、`sameAs`；要求端点类型显式且兼容。多个domain/range形成同时满足语义，不是任选；属性类型/单位不同不能直接强等价。

## 冲突检测

| 原冲突类别 | 例子 | 核对方法 |
|---|---|---|
| 同名异义 | “零件”分别只指机械与电子零件 | 比较定义、成员范围和来源，保持身份独立 |
| 异名同义 | “备件”与“零件”可能部分重合 | 定义相同才能等价；用途/库存状态差异可能应为子类或关联 |
| 结构差异 | A→B→C与A→C | 比较传递蕴含，父类列表不相同不等于冲突；检查互斥、匿名限制及等价 |
| 属性差异 | 同名价格decimal与string | 比较类型、币种、单位、方向、基数和历史语义；显式转换而非统一转字符串 |
| 事实/规则冲突 | 两模型对同对象产生互斥结果 | 保留前提、身份来源、时间与规则依据，分析组合命中和来源适用性 |

原 `get_parents`/父列表比较只提供差异线索，不能自动判同名异义或覆盖另一方。对齐后检查新增蕴含与等价传播；互斥、功能性、基数和sameAs传播必须由实际DL检查/数据约束和黄金案例验证。

## 冲突解决与决策树

四种原策略均保留，并要求明确依据：

1. **选择优先源**：仅按已确认权威、生效期、范围决定；不能默认第一个输入胜出。记录被替代公理及理由。
2. **合并属性/公理**：先验证类型、domain/range、单位和限制兼容；对象字典的“缺项补齐”不足以证明语义兼容。
3. **创建新概念**：给出新定义、范围、IRI与来源对应，必要时设共同上位类或桥接；不只生成一个新名字掩盖原冲突。
4. **保留两者及命名空间**：同名异义保持稳定IRI，补标签/定义，已有IRI不因改显示名重建；域间关系明确表达。

决策顺序：同名异义已证实→保留独立身份/定义；异名同义已证实→复用或等价；结构差异→先比较蕴含与范围，再决定桥接/来源优先；任一语义未决→保留差异和人工项。来源未确认的矛盾不得自动消解，已有人工处理决定不回退成确定机器结论。

## 构建执行

基本物化合并使用各文档独立空白节点作用域，保留所有源三元组（集合去重允许），不偷偷改类/属性IRI。可执行：

```powershell
python -B -X utf8 skills/ontology-fusion/scripts/fuse_local.py merge --source <模型A> --source <模型B> --output <新装配目录>
python -B -X utf8 skills/ontology-fusion/scripts/fuse_local.py merge --source <模型A> --source <模型B> --mapping <已审映射.ttl> --output <另一个新装配目录>
```

第二条在联合图新增已审桥接公理，**不改名、不删除源公理、不自动修复冲突**。需删除或重构时先在新源版本施加明确增删补丁，使用[迁移方法](../../ontology-migration/SKILL.md)。输入含imports时此脚本拒绝，不把未载入依赖的并集称完整融合；应先固定显式本地闭包/声明装配范围，再运行。

若采用imports模式，使用具名本体头作主语、导入本体IRI作宾语：

```turtle
@prefix owl: <http://www.w3.org/2002/07/owl#> .
<urn:example:integration> a owl:Ontology ;
  owl:imports <urn:example:model-a>, <urn:example:model-b> .
```

本体IRI与本地文件位置通过[OWL-DL本地映射](../../../Ontology-tools/OWL-DL.md#多模块与离线导入)或实际后端加载计划绑定；不能以随机 `Graph.identifier` 和 `Namespace(file://...)`造导入公理。不联网检查导入；导入入口须明确还需要哪些文件，不能宣称已完整合并。

输出 `result.ttl`、输入快照、调用脚本及共用模块的快照/指纹、`report.ttl`、`report.md`及SHA256清单；输出目录须在方法库及源本体/证据包之外。CLI0仅表示图操作与重解析同构通过，CLI2表示路径、映射、解析或转换失败。此脚本不运行DL或SWRL，不提供“自动融合已无冲突”的结论。使用的共用本地RDF模块位于[迁移工具](../../ontology-migration/scripts/local_graph.py)，全在Ontology内部。

## 融合后验证、报告与清单

- 纯装配：联合原图与结果图同构（空白节点无关）；有映射则检查源并集加已审公理的预期图。比较缺失与意外新增，数量只辅助诊断。保存完整差异图；界面可展示前10条但不得只保存10条。
- 检查联合TBox和明确ABox的全局一致性/具名不可满足类；实际SWRL、前后SHACL和跨域能力问题分别测试。
- 用相同受控事实比较融合前后新增/消失蕴含，检查等价/身份传播、规则冲突和关系方向；旧来源模型一致不证明联合模型一致。
- 报告保留五部分：输入模型及类/属性/规则计数；候选与确认对齐数及潜在冲突；按冲突类型列数量/策略/依据；融合结果计数和文件版本；完整性、一致性、回归实际结果。补充未决项、来源指纹、命令、被替换公理及回退位置。
- 回退保留各来源快照、已审映射、源补丁和旧集成构建清单；恢复旧版本需按明确发布流程，本地生成不自动进行生产切换。

逐项验收：输入概念结构已盘点；候选与已证实等价分开；映射与依据可追溯；冲突清单完整；策略有依据；装配实际执行；联合一致性/规则验证实际完成；报告包含未决/失败；每个融合决策可回溯。语义未决不以修改置信度解决。
