# 字段、身份、关系与证据契约

本文件指导设计 `mapping.ttl`、输入事实和相应 SHACL 约束。它不提供接口适配器；实际映射是否实现必须单独登记。总结构见[输出规范](../../../CONTRACT.md)。

## 1. 字段映射记录

每个参与推理的字段至少记录以下内容：

| 维度 | 内容 |
|---|---|
| 来源定位 | 来源 ID、系统/文件/接口对象、字段路径、记录定位方式 |
| 目标语义 | 目标类、目标属性、字段业务含义和原始/派生角色 |
| 身份与粒度 | 业务键、记录键、快照键、所属对象与周期 |
| 数据类型 | 原类型、目标 XSD 类型、合法词法形式与解析规则 |
| 数值口径 | 单位、币种、精度、比例、转换、舍入及来源 |
| 空值与错误 | 缺字段、null、空串、失败、无业务和非法值分别如何处理 |
| 时间 | 事件时间/入库时间/生效时间、时区、起止边界和快照时间 |
| 实现 | 未实现/已实现/已验证、转换入口、版本及验证证据 |

不使用一个通用“备注”字段隐藏影响结果的条件。枚举映射应逐项对应，未知代码明确拒绝或保留未知状态，不能直接归入默认类别。

## 2. 身份与关系映射

IRI 是图中的标识，不自动证明对象一致。声明：

1. 来源键在哪个租户、系统或数据域内唯一。
2. 缺键、重复键、键变更及多版本如何处理。
3. IRI 如何由键稳定构造，是否需要保留敏感标识。无需直接暴露的个人标识可以通过项目已定义的替代标识映射。
4. 关系两端的连接键及额外范围，例如主体、周期、版本、事件窗口。
5. 无关联、多个候选或跨范围关联时如何处理，是否允许进入推理。

`owl:sameAs` 表示很强的身份相同语义，不是“可能匹配”“同名”或“需人工合并”。`owl:hasKey`、逆函数属性或函数属性具有各自的逻辑语义，不应充当数据库唯一索引；输入重复、复合键和关联范围仍须显式验证。

关系有发生时间、数量、角色或来源版本时，可以使用关联/事件个体，例如“检查记录 → 检查对象”。不要把属于某次检查的数值直接挂到永久资产对象上，导致多个时期事实混为一谈。

## 3. 数量和时间转换

同一量纲也可能有不同业务口径，例如含税与未税、累计值与本期值。先核对口径，再执行单位转换。金额使用精确十进制；没有舍入规则时，记录未确定范围或保留精确中间值并阻断受影响的自动金额结论，不自行四舍五入。

时间字段说明采用 `xsd:date`、`xsd:dateTime` 或后端实际支持的其他类型。表示唯一时点时需要可解释的时区；原材料只有日期，不擅自补出发生时间。窗口是否包含起点和终点必须来自业务规则或实际确认。

字段转换、聚合计算和业务结论分开记录。映射文件中的公式文字并未执行；如果由适配器计算，必须保留输入、转换版本、结果与测试证据，且不能在适配器中另写一套与 SWRL 平行维护的政策。

## 4. 聚合前声明集合

“同类次数”“责任合计”“最近一次”等表达先拆成可检查的集合契约：

- 聚合目标对象及分组键。
- 候选记录来源与查询快照。
- 纳入、排除与状态条件的依据。
- 时间窗、版本选择、去重与撤销记录处理。
- 集合完整性的证据与缺失记录时的行为。
- 聚合运算、单位、负数、空集合、舍入和分摊尾差口径。

未查到记录与“已确认集合为空”不同。来源接口只返回一页数据时，不能直接把当前页计数当作完整次数。无法确认成员全集时，不能把局部汇总作为确定的全量结论。

## 5. 保留原值与证据

输入图写业务事实，证据图或注释结构记录来源。可选择所用工具实际支持的 RDF reification 或命名图；不要假定所有后端都支持同一种 RDF-star 表达。每条业务字段值和关系边均应能回到真实来源位置。

下面是独立的虚构结构示例。`ex:record-1` 的字段值被明确断言，重述节点只用来挂接证据；RDF reification 本身不会自动断言被描述的三元组。

```turtle
@prefix ex: <https://example.org/demo#> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix dcterms: <http://purl.org/dc/terms/> .

ex:record-1 a ex:Inspection ;
    ex:recordId "R-001" ;
    ex:inspects ex:asset-1 .

ex:sampleSource dcterms:title "虚构结构样例"@zh ;
    dcterms:description "synthetic；用于说明证据结构"@zh .

[] a rdf:Statement ;
    rdf:subject ex:record-1 ;
    rdf:predicate ex:recordId ;
    rdf:object "R-001" ;
    dcterms:source ex:sampleSource ;
    dcterms:description "样例记录 R-001 的编号字段"@zh .

[] a rdf:Statement ;
    rdf:subject ex:record-1 ;
    rdf:predicate ex:inspects ;
    rdf:object ex:asset-1 ;
    dcterms:source ex:sampleSource ;
    dcterms:description "样例记录 R-001 的对象关联"@zh .
```

示例只演示两条业务事实的证据方式；完整项目仍须声明类、属性、身份和类型事实来源，并验证证据覆盖。来源引用说明记录声称来自哪里，不证明内容真实、未经篡改或集合完整。

## 6. 从契约导出检查

为单值、必填、类型、枚举、范围和关系目标建立适用的 SHACL 约束。复合唯一键和跨对象/时间范围检查，按后端支持选择 SHACL-SPARQL 或经过验证的本地校验，不写一个不可执行的注释充作约束。

检查错误至少定位对象、字段或关系、违反的约束和实际值。区分“输入不合法”与“业务条件不满足”：前者阻断依赖它的判断，后者可能是有效规则结果。不能以填零、删除冲突记录或改成 synthetic 标签让错误输入通过。

最后核对每个规则输入都已映射，每个映射都存在目标属性，每个关系都有两端身份及连接规则，每项转换都有实现状态，全部验证声明均可指向实际运行证据。
