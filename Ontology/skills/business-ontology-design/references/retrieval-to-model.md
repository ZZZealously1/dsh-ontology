# 从知识库检索结果到本体

用于用户要求从知识库、RAG结果或其离线导出材料逆向建模的任务。它补充[业务设计](../SKILL.md)的来源获取步骤，不要求特定平台，也不提供知识库连接器。已有本地文件时按[文档抽取](document-to-model.md)处理；已有本体融合时转[变更与复用](../../ontology-validation/references/change-and-reuse.md)。

## 1. 确定素材范围与读取方式

先登记能力问题、目标知识库或已提供导出文件、文档范围、版本/时间、允许读取的范围，以及本次不能访问的内容。用户已提供离线材料时可直接使用；未获得外部读取授权时先处理现有材料，示例中的工具调用不构成连接外部系统的授权。

连接器可用且在授权范围内时，先核对其实际接口、参数约束、分页与返回结构。知识库列表分页和片段检索召回是两件事：列出了所有库，不表示召回了库内全部条款。`IndexId`、TopK、重排数量、超时和工具名称都是平台及版本参数，按当前接口确定，不把示例中的10、50、3～5或50KB写成通用门槛。

检索语言与查询词跟随材料；用原业务词、同义词和上位/下位概念补充检索。大结果可以分批读取或委派提取，但须保留原文定位与冲突；不要求凑满固定实体数、关系数或顶层类数。

## 2. 按能力问题组织检索

建立主题覆盖记录，逐轮补足决定性信息：

| 记录 | 最低内容 |
|---|---|
| 检索目标 | 对应能力问题、要核对的术语/字段/条件/例外 |
| 实际请求 | 查询词、过滤条件、连接器/版本、实际参数、检索时间 |
| 来源与返回 | 知识库/文档/片段ID、标题、版本、页/章节或定位、排序/分数（如返回） |
| 证据快照 | 获准保存的原片段或本地快照位置、SHA256；不能保存时说明复核限制 |
| 覆盖与缺口 | 已核对主题、遗漏分页或文档、截断、失败、尚未找到的例外/公式 |

先检索定义和对象，再核对关系、身份、条件、单位、例外和时间范围。条件命中后查其上下文、引用条款、否定与例外；不能仅用最高分片段生成确定规则。重复返回同一片段按来源身份去重，不把多次召回当成多个独立佐证。

同一概念在不同版本、组织或流程阶段有不同定义时，先分开记录；按已确认的适用范围和来源权威性处理，不按相似度、排序或出现次数选政策。只有摘要、没有原条款时明确证据不足，不补造原文。

## 3. 把抽取候选与已采用语义分开

把素材整理为候选实体/术语、关系、属性和分类，但逐项做设计判断：

- 名词可能是类、个体、角色、字段值或文档标题；动词可能是关系，也可能描述某次事件或业务动作。
- 分类树可能是组织目录或检索标签，未必是 `rdfs:subClassOf`。确认“每一个A都是B”后才建立继承。
- 关系写成“主体—谓词—客体”，核对两端身份、方向、时间与作用域；涉及数量/角色/生效期时考虑事件或关联个体。
- 抽取出的条款先列前提、例外、结论和依据，再决定放入OWL、SWRL、SHACL或应用层状态；文本出现“批准”不表示动作已获授权或已经发生。
- 来源中的枚举、基数、互斥、唯一性、传递性必须逐项有依据；不能为满足模板而补公理。

候选登记状态如“待核对、已采用、排除、冲突”应有明确含义和理由；它是设计审查记录，不构成审批权限。检索分数仅描述检索排序，不代表事实真值、模型置信度或用户确认。

## 4. 落到统一的 ontology 目录

按照[输出规范](../../../CONTRACT.md)维护原生语义文件：

- `provenance.ttl`：来源身份、定位、版本、获取方式与能力问题/规则/事实的关联；需要详细检索记录时可另放 `sources/retrieval.ttl` 并从来源图引用。
- `mapping.ttl`：片段或结构化字段到类/属性/事实的转换与实现状态。抽取候选不是已验证事实；无法回溯的推测不直接进入ABox。
- `subontologies/`、`rules/`、`data/`：分别维护TBox、原生SWRL和获准使用的事实快照；不把完整模型复制进动态ABox。
- `docs/`：按[领域说明模板](../../../templates/domain-doc.md)解释模型、规则、素材覆盖和缺口。保留知识库主题及文档清单的证据定位。

这些检索记录可使用项目自定义RDF词汇，但须说明词汇含义与实际解析实现；不生成JSON，也不把可读文本SWRL改后缀伪装成RDF/XML。脚本可以辅助初次生成语义文件或从原生源重建集成，交付后须明确唯一维护源，不同时在Python中手写另一套业务条件。

## 5. 验收检索范围与推理范围

来源抽取检查与推理检查分别留证：检索命中不证明材料全集完整，RDF解析不证明规则已执行，固定点不再新增也不能证明所有规则均已加载。至少用独立预期核对相关分类/关系/计算结果，并检查缺少决定性片段、矛盾版本、关系方向错误或遗漏规则时的行为。

对于“全部、仅有、未发生、累计、最高”等依赖全集的结论，需要明确数据全集和快照证据；有限TopK片段不能证明这些结论。无法确认时保留缺口或用户已确定的人工处置，完成不受影响的建模部分。

只具备离线片段时将来源获取标为离线导入；没有真实检索和推理调用记录时分别标 `not_run`。项目报告说明哪些能力问题有证据覆盖、哪些材料未覆盖，不把模型中已有几个类当作业务范围完整的证明。
