# 能力问题与可验证范围

能力问题（Competency Question，简称 CQ）是用户希望模型在指定事实和范围内回答的问题。它用来约束模型大小、选择推理任务并设计黄金案例。文件结构见[输出规范](../../../CONTRACT.md)。

## 一条问题应包含什么

| 项目 | 要写清的内容 |
|---|---|
| 稳定 ID | 例如 CQ-01；不以显示文案作为唯一身份 |
| 问题 | 哪个对象，在何种时间/业务范围内，回答什么 |
| 输入 | 需要的类、属性、关系、快照和集合完整性 |
| 输出 | 事实集合、分类、关系、决策状态或结果 |
| 依据 | 制度位置、术语定义、查询需求或实际确认 |
| 不足时行为 | 缺失、冲突、无匹配、非法输入如何表现 |
| 验收 | 案例 ID、独立预期以及哪些反例必须被识别 |
| 边界 | 不回答的近似问题，不代表的下游动作 |

将上述内容用项目定义并说明含义的 RDF 词汇记录到 `provenance.ttl`，通过稳定 IRI 关联模型、规则和案例。Markdown 可以呈现同一信息，但不成为第二份业务语义源。

## 区分问题类型

| 类型 | 结构示例 | 所需证据 |
|---|---|---|
| 事实查询 | “指定资产有哪些明确关联的检查记录？” | 查询、输入快照、独立预期记录集合 |
| 分类推导 | “哪些实例满足已定义的合格类别？” | 实际公理/规则、事实、推理结果与依据 |
| 关系推导 | “哪些对象之间可推出指定关系？” | 两端身份、规则前提、关系结果 |
| 决策判断 | “给定完整事实，本次应输出哪个处置建议？” | 条款、例外、应用状态语义、独立预期 |
| 业务执行 | “是否已经提交、审批或办理？” | 真实操作记录与授权；不能仅由建议结论证明 |

表中示例是结构说明，不提供任何业务通过条件。分类成员定义、合格阈值和动作权限仍需项目来源。

## 从宽泛要求拆出问题

以“判断记录是否能用于后续分析”为例，可拆为：

1. 记录是否能够唯一定位？这是身份和数据质量问题。
2. 记录是否关联到请求的对象与时间范围？这是数据关联问题。
3. 它是否满足来源明示的资格条件？这是公理或规则问题。
4. 输入不全或规则同时命中时，应用如何输出？这是应用契约问题。
5. 谁可以采用这个结果办理业务？这是权限和流程问题。

不要用一个“是/否”字段把五个问题合并。第 1、2 项通过不证明第 3 项成立，第 3 项成立也不证明第 5 项已获授权。

## 为每条问题准备案例

先从来源独立编写预期，再设计输入。每个案例只在有明确测试目的时引入新差异，避免因多个变化同时出现而无法判断失败原因。

- 正向：前提明确成立，产生预期分类、关系或结论。
- 边界：比较运算两侧与等号是否符合条款；边界值来自真实规定或标注为纯结构示例。
- 信息不足：缺失关键事实时不产生未经支持的否定或确定结论。
- 冲突：相互矛盾的事实、规则结果或来源能够被定位；所选后端/应用如何报告须明确。
- 非法输入：类型、身份、关系范围或证据缺失被拒绝或按已声明策略隔离。
- 范围反例：同名不同对象、不同周期、已过期版本或不属于集合的记录不会被误关联。
- 人工事项：输出明确的人工状态，测试通过不表示人工环节已执行。

并非所有项目都存在上述每一种分支；不适用时说明原因，不杜撰规则来凑齐案例数。规则覆盖、公理覆盖、条件边界覆盖与能力问题覆盖分别报告。某条规则曾被触发一次，不等于它的全部条件组合已验证。

## 交付前核对

逐条沿“能力问题 → 来源 → 所需事实 → 模型/规则 → 案例 → 实际结果”检查是否有断点。未实现的问题保留状态与原因；测试预期不能通过复制当前运行器输出补齐。

OWL 的开放世界语义下，未推得某事实不等于它为假。需要“没有匹配记录”“从未发生”或“已经枚举全部成员”的结论时，必须说明数据完整性和所选查询/应用语义，不能从缺少三元组直接推出。
