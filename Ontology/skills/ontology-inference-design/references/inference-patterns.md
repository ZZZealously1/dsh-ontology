# 推理模式与边界

本参考帮助选择表达方式，不定义业务政策。交付格式见 [输出规范](../../../CONTRACT.md)。下列表达都是方法示例，不能直接成为项目的已批准规则。

## 从问题选择机制

| 问题 | 建模方式 | 必须单独验证 |
|---|---|---|
| 某类的实例还属于哪些上位类 | OWL 类层次及分类推理 | 实际后端的 OWL 支持范围、类可满足性和一致性 |
| 已知关系可否推出逆关系、传递关系 | OWL 对象属性公理 | 是否支持该公理、关系方向和范围是否正确 |
| 多项已有事实成立时推导一个标记 | SWRL 规则 | 原子、内建、变量绑定及冲突归并 |
| 输入是否缺字段、类型错误、关联失配 | SHACL 形状及项目完整性检查 | 目标对象是否真的被选中，校验范围是否完整 |
| 找出沿关系链可达的对象 | SPARQL 属性路径 | 查询图、路径是否含零跳、重复与截断 |
| 计算账期内已退金额、次数或金额分摊 | 明确口径的聚合/算术实现 | 集合完整性、去重、单位、精度、舍入和后端能力 |
| 当前状态允许执行某业务动作吗 | 带时间与授权条件的业务决策 | 业务批准与动作执行；逻辑推导不执行动作 |

不要为统一形式强行把所有问题变成 SWRL。纯查询任务可按查询预期验收；如果宣称推理能力，就必须验证实际新增的类型、关系或结果。

## 模式一：分类和关系推导

设 `PremiumCustomer rdfs:subClassOf Customer`，且某对象为 `PremiumCustomer`，OWL 后端应能回答它是否为 `Customer`。测试输入中只放前者，独立预期为后者；输入先写好两种类型不能证明发生了推理。

逆属性、传递性、等价类与属性链都以同样方式设计“原始事实不足、推理后可回答”的小案例。不要把所有这些能力捆成一个“OWL 支持”勾选；后端只支持其中一部分时逐项声明。声明 `domain` / `range` 常会带来类型推导，不是拒绝错填对象的输入验证规则。

`owl:sameAs` 会影响同一对象的全部断言；它不是普通的相似关系或模糊匹配。身份合并需先有证据与项目策略，不能为消除重复而直接添加。

## 模式二：多事实合取

可用“物料的库存量小于同地点、同时点和同单位的安全库存量”说明规则结构。阈值来自输入中有依据的安全库存值，示例不设固定数值。

建模前先回答：库存是物料全局属性，还是某次库存快照的属性？若按地点和时间变化，应以快照为规则对象，关联物料和地点。仅对同一物料绑定两个任意数值，可能把不同地点的数据错误组合。

前提缺失时，SWRL 通常不能推出结论；是否报告“未知”、拒绝输入或转人工，由项目应用语义与形状约束决定。不能自动推导相反结论。

## 模式三：互斥区间与冲突

有来源阈值 `T` 的分类，分别审查 `< T`、`= T`、`> T` 的覆盖和相交。不要自行添加容差，金额和单位不明时不比较。若来源只给出两个不完整区间，保留缺口。

多条规则命中不必然是逻辑矛盾：对象可以同时属于多个类。决策只允许一个结果时，需要显式说明如何判断冲突；即使两个规则输出相同结果，也不能未经约定就合并。优先级不是 SWRL body/head 自带的“先到先得”行为。

## 模式四：聚合、计算和时间

计数/金额合计要先明确业务键、统计对象、过滤条件、账期边界、退款与撤销记录、重复页及数据完整性。`COUNT` 能运行不代表它统计了正确的业务集合。

金额使用精确十进制。公式可被推理器支持、外部适配器实现或尚未实现；三种状态应分别声明。适配器必须由原生语义可追溯地派生或有清晰的非政策计算契约，不能在 Python/Cypher 中另写一套条件。舍入模式、位数、执行阶段和分摊尾差没有依据时保留人工处理。

时间规则须说明事件时间/查询时间、时区、生效区间与迟到数据。SWRL 推导断言一般不会随着新事件自动撤销；状态变化需要快照、版本或重算策略，不应把单调推导直接当成工作流状态机。

## 模式五：约束与证据

SHACL 检查的输入图必须明确：原始事实，还是已声明推理闭包后的事实？前置检查可阻止坏数据参与决策，后置检查可验证推导结果；若后置检查依赖某类推断，其推断阶段和图版本要在执行说明中列明。

形状没有命中目标节点时，可能得到空校验通过。验收应记录目标对象数量、期望目标类型及非空案例。来源三元组的存在只能证明“记录了来源”，不能证明来源真实、有效或数据集合完整。

## 用例设计小表

| 类别 | 设计方式 | 应观察的证据 |
|---|---|---|
| 正向 | 最少的必要事实满足所有条件 | 新断言/明确结果及命中规则 |
| 单条件反例 | 每次只破坏一个关键前提 | 不产生该结论；其他规则不误命中 |
| 边界 | 来源阈值两侧及等值 | 与比较操作一致，未自加容差 |
| 缺失/非法 | 缺值、空串、错误词法或类型 | 按约定未知或拒绝，而非当作零 |
| 错误关联 | 相同名称不同身份、跨时间/对象 | 不发生错误连接 |
| 冲突/人工 | 同时触发多个决策或人工条件 | 显式状态与规则依据 |
| 不支持 | 插入声明范围外的公理/内建 | 明确拒绝或标记未执行，不静默忽略 |

用例总数不等于规则覆盖。分别列明规则/公理覆盖、关键条件覆盖与未覆盖项；未知、拒绝和人工预期同样是独立可验收结果。
