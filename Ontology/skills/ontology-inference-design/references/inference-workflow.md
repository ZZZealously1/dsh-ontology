# 推理规则设计手册

## 规则类别与选择

| 类别 | 输入→结果 | 建模边界 |
|---|---|---|
| 推导 | 已知属性/关系→新的属性/关系 | 原示例“安全级SC1→质保级QA1”仅说明模式，不是项目政策 |
| 计算 | 明确参数→公式值 | EOQ=`sqrt(2DS/H)`为设计示例，公式来源、单位、定义域和后端算法需核对 |
| 约束 | 满足违规条件→复核标记 | 库存小于明确安全库存可推标记；必填/类型错误用SHACL，不能将缺字段当违规事实 |
| 分类 | 属性条件→类型或分类码 | 供应商评分>90、年消耗额>100万元均为合成示例值，不作为实际阈值 |
| 时序 | 当前快照与条件→下一状态建议/事件 | SWRL单调增加事实，不删除旧状态；动作执行和审批本身不在推理授权内 |

## 四步设计

**1. 识别规则类型。** 记录来源位置、版本/生效期、规则IRI、所属领域、对象粒度、时间窗、条件、例外、结论、缺口和后端。区分预测/建议/确认/已执行；分类到类与输出字符串分类码不是同一语义。

**2. 定义前提。** 明确类原子、对象/数据属性原子、值限制和多个AND条件，所有连接变量要表达同一对象或经过已声明关系。字段名相同不能证明处于同一周期。正向SWRL无默认否定；`notEqual`比较两个已绑定值，不表示字段不存在。变量和内建输出绑定范围随后端能力核验。

**3. 定义结论。** 常规结论可新增类型、对象关系、数据值或标记；不能通过SWRL head修改或撤销旧值。创建新实例需专门生成机制/扩展、稳定身份和终止契约，普通安全SWRL不应自动造新个体。新事件由有声明的适配程序生成后再作为输入；不要伪装为已支持的规则能力。

**4. 验证逻辑。** 每个必要条件有来源且齐备，冗余条件确有适用意义；结论能从条件推出，无未绑定变量或跳跃；补缺失、空值、零、负数、边界、极值、多值、重复及冲突案例。不能用调整规则顺序解决没有语义依据的互斥问题。

以下为可读规则记法，**不是可解析Turtle**。序列化时使用声明的 `swrl:Variable`、具体属性原子和RDF列表；`swrlx:buildURI` 不能代替变量声明，泛化 `PropertyAtom` 不能代替具体对象/数据属性原子：

```text
Snapshot(?s) ∧ stock(?s, ?qty) ∧ safetyStock(?s, ?limit)
∧ swrlb:lessThan(?qty, ?limit) → needsReview(?s, true)
```

正式 `.swrl` 使用[原生RDF/XML模式](swrl-sparql-patterns.md)，变量为显式 `swrl:Variable` IRI；对象属性用 `IndividualPropertyAtom`，数据属性用 `DatavaluedPropertyAtom`，内建参数用RDF列表。该结构需后端实际加载执行，不把可读记法直接保存为 `.ttl`。

## 正确性保障

### 来源回译

依次保留：业务原文→前提/例外拆解→形式化规则→自然语言回译→逐项对照→差异和处理。原示例“年消耗金额超过100万元的备件属于A类”回译为“对每一备件x，若同一约定周期年消耗金额c严格大于100万元，则分类码A”；核对严格大于、金额币种/单位、周期、对象和例外。没有真实来源时仅标演示，不能将其加入项目有效规则。

回译检查不只看文字近似：`>`与`>=`、分类码与类、当前值与历史值、任意成员与全部成员、金额原值与已退费值、单条与合计都可能改变结论。规则来源冲突保留两方依据和未决状态，不自行优先。

### 独立单元与组合测试

每条规则IRI至少关联适用的正向/反向/边界案例；多规则场景覆盖交叠条件、继承/等价、冲突结果、反复命中和固定点。测试预期由来源或独立计算给出，不能让当前推理器输出成为黄金答案。负例分为“不应推导此值”和“应推导否定值”，二者不能混淆。字段缺失究竟阻断还是保持未知，按输入契约。

规则的业务合理性由回译和案例确认，执行正确性由后端实际运行确认，两者均需要。具体测试包格式及命令见[验证手册](../../ontology-validation/references/validation-workflow.md#3-规则正确性与独立测试)。

### 实际推理器验证

加载冻结TBox、规则、ABox→核对支持范围→执行→保存结果/闭包→比较预期→复跑。原列OWL API+SWRL API、Pellet、Protégé为可选技术方向，不代表随库实现。当前本地规则后端支持范围见[PROFILE](../../../Ontology-tools/PROFILE.md)；[HermiT入口](../../../Ontology-tools/OWL-DL.md)只检查OWL DL，不执行SWRL。不能因“Java加载成功”或界面显示规则就报告规则执行成功。

## 数值准确性保障

### 类型

整数可用 `xsd:int`/`xsd:integer`，十进制量可用 `xsd:decimal`，真正浮点量可用 `xsd:float`/`xsd:double`；核对后端是否保留类型、数值空间、NaN/INF及溢出行为。`xsd:decimal`本身不保证计算引擎始终十进制精确，开方的非有理结果也无法以有限小数精确表示。

### 公式、单位与来源

EOQ设计示例：`Q = sqrt(2 D S / H)`。D为年需求量（件/年），S为每次订货成本（元/次），H为每件每年持有成本（元/(件·年)）；“每次”视订货事件计数单位，结果Q为订货批量（件）。正式使用需来源原文、假设（需求稳定等）、符号定义与量纲；仅写“《库存管理》教材”不足以证明权威出处，需提供页码/版本或项目明确依据。

### 参数范围

定义域至少核对分母非零及开方输入非负；额外业务约束“D、S、H均大于0”须有来源。允许零需求时的行为、负值能否代表退货等由业务定义，不根据演示自行确定。可读模式：

```text
SparePart(?x) ∧ demand(?x, ?d) ∧ orderCost(?x, ?s) ∧ holdingCost(?x, ?h)
∧ validParameters(?x, true)
∧ multiply(?ds, ?d, ?s) ∧ multiply(?twoDs, 2, ?ds)
∧ divide(?v, ?twoDs, ?h) ∧ SquareRootBackendFunction(?q, ?v)
→ economicOrderQuantity(?x, ?q)
```

`validParameters`的来源约束与`SquareRootBackendFunction`具体IRI必须落实到实际支持的模型/后端，以上仅设计记法。**没有通用 `swrlb:sqrt` 执行保证**。不支持时报告未实现，并选经验证的扩展或可追溯计算事实；不能另写一套无来源Python业务政策绕过原生模型。

### 结果精度

记录精度（绝对/相对误差或精确值）、舍入模式、位数、单位换算时点、尾差归属及来源。原演示D=120、S=500、H=3000得 `sqrt(40)≈6.32455532`，独立数学参考可核对公式实现；是否输出6.32以及如何比较须先有精度契约。移除原 `pytest.approx(..., rel=0.05)` 默认5%容差。精确整数/十进制比较或有依据容差均可，别把所有浮点比较统一改成任意宽容差。

## 原内建速查表的逐项维护

以下保留原表所有函数用途；这些是**设计检查项，不是当前后端可执行列表**。标准词汇完整说明由[OWL/SWRL参考](../../../references/owl-swrl/index.md)维护；实际使用应核验精确IRI、参数方向、类型、错误输入、输出绑定及成功/负例能力探针。

| 原名称 | 用途/维护处理 |
|---|---|
| add / subtract / multiply / divide | 加、减、乘、除；核对类型、溢出、除零，通常输出参数在前；local-rules-v1 不支持；[计算配置](../../../Ontology-tools/CALCULATION.md)支持二元形式和输出绑定 |
| sqrt | 平方根；不视为通用标准swrlb内建，需具体扩展IRI与验证 |
| pow | 幂；应核对标准/后端 `swrlb:pow` 的类型与参数，不推定可用 |
| abs / round | 绝对值、舍入；round规则不等于业务财务舍入，不推定小数位能力 |
| equal / notEqual | 两个已知值比较，notEqual不是缺失或闭世界否定 |
| lessThan / lessThanOrEqual / greaterThan / greaterThanOrEqual | 比较，保留边界区别并验证类型支持 |
| contains / startsWith / endsWith | 字符串包含、前缀、后缀；核对字符大小写、语言/编码及后端 |
| length / concat | 原名不直接冠以swrlb；标准名称检查 `stringLength` / `stringConcat`，后端扩展另记 |
| year / month / day | 原名不作为标准通用IRI；日期/时间分量按后端支持的日期函数及精确签名实现 |
| addDays | 原名不作为标准通用IRI；核对duration、时区、日历边界及后端扩展 |

## 五种常见模式

1. **阈值分类**：`Entity(x) ∧ value(x,v) ∧ greaterThan(v,limit) → category(x,code)`。阈值来自有效来源或已验证参数；原ABC/100万元只是演示，补相等边界和单位。
2. **公式计算**：绑定所有参数→检查定义域→计算中间值→输出值。保留2×参数1×参数2÷参数3再开方的EOQ模式，后端不支持就不宣称已执行。
3. **状态流转**：`Order(x) ∧ status(x,"Submitted") ∧ approvalResult(x,true) → eligibleNextStatus(x,"Approved")`。保留原提交且批准的条件意图，改为派生下一状态资格；原 `hasStatus="Approved"`会与旧值并存，不能当更新。
4. **约束检查**：已知库存小于已知安全库存→需补货/复核标记；原 `hasViolation`及`hasViolationType`可表达异常事实，但不能代替SHACL完整性验证或实际补货动作。
5. **推导属性**：来源支持的安全级SC1→质保级QA1。常量、对象/数据类型、适用版本均需来源；一般模式 `derivedValue`须换成有绑定/来源的值。

## 常见错误、停止条件及清单

| 问题 | 修正 |
|---|---|
| 输入变量未绑定或输出方向错误 | 列出每个变量来源与内建绑定模式，检查完整参数；不靠调整显示顺序碰运气 |
| 字符串用数值比较、类与分类码混用 | 修正原生属性声明、字面值类型及转换来源 |
| 缺定义域/例外条件 | 补来源支持的条件和缺失/除零反例，不自造业务条件 |
| 循环依赖 | 单调有限固定点可能合法；检查是否生成无限新值/个体或资源上限，不能一律要求“改顺序” |
| 精度损失 | 根据精度契约选择表示、计算与比较；不得默认5% |
| 同一条件得互斥结论 | 保留冲突前提与来源；明确条件互斥/有效期/已确认优先来源，不臆造规则优先级 |

手算不符、推理不符、执行报错、多规则冲突、边界异常时保留实际证据，定位公式/参数、条件完整性、变量类型、冲突来源与边界；缺口未决则保持人工处理或阻塞，不能标“通过”。

验收清单保留：语义与来源一致；前提充分且必要；结论可推导；范围/类型正确；公式来源和单位可追溯；正反/边界/组合案例；真实后端执行；规则冲突受控；边界和精度口径明确；结果与解释可复核。
