# 推理与查询实施

本手册负责选择执行机制、编写原生表达与查询、交接实际后端。业务前提、公式、例外、回译和独立预期先按[规则设计](inference-workflow.md)确定；必要条件与组合案例的核对见[规则设计与测试](rule-design-and-tests.md)。共享原则与交付格式分别遵守[公共原则](../../../common_rules.md)和[输出规范](../../../CONTRACT.md)。

## 输入与实现选择

输入为能力问题、对象身份和粒度、OWL模型、来源条款、数据映射、已确认的人工事项、独立预期及拟用后端的能力声明。没有后端时可以设计和审查，执行状态仍为未验证；语义未定的候选与实际执行规则分开。

按[推理模式](inference-patterns.md)选择实现，不强行把所有问题写成SWRL：

| 所需能力 | 实现与须核验的边界 |
|---|---|
| 类别、身份或关系的逻辑后果 | OWL公理及支持该语义的推理器；逐项核对构造支持、分类与一致性能力 |
| 多项事实共同成立时增加断言 | SWRL；核对原子、变量绑定、数据类型、内置函数和规则组合 |
| 输入完整性或结果形状 | SHACL；明确校验原始图、推导图或闭包以及前后执行阶段 |
| 筛选对象、关系路径或读取结果 | SPARQL；明确查询图、对象范围和独立预期 |
| 聚合、舍入、优先级或状态变化 | 有来源的应用执行契约与兼容实现；不能假定普通SWRL自动提供 |

## 原生表达与查询

1. 按[原生SWRL/SPARQL模式](swrl-sparql-patterns.md)使用真实 `swrl:Imp`、body/head列表和原子；`.swrl`为RDF/XML。核对head变量约束、对象关联、内置函数签名与绑定方向。规则归属其业务结论所在领域，跨域引用声明身份连接和依赖，不复制共享术语。
2. SWRL的body表示条件合取，不能把书写顺序当业务优先级。递归、计算绑定、生成个体、断言撤回和状态更新分别核验后端；时序采用带时间的事实/事件或候选状态，不把单调推导当工作流状态机。
3. 为查询记录文件、参数、原始/推导/闭包图、对象与时间范围、路径零跳/重复处理及预期结果。`NOT EXISTS`与聚合只针对指定图；数据集合未确认完整时，不能解释为业务否定或完整总量。
4. 对决策结果明确缺值、无匹配、多规则命中、冲突、人工事项和技术错误的不同含义。人工状态须显式建模，不由日志文字猜测；推导候选结论不表示审批、消息、下单或退款已执行。

## 后端交接与完成条件

- 交接原生模型/规则、显式ABox、形状、查询、来源映射和独立案例；布局及候选规则隔离遵循输出规范。默认集成文件由源重建，事实另行加载，不能因文件存在而认为已完整参与推理。
- 按[执行方法](../../ontology-execution/SKILL.md)验证实际加载、支持范围和能力探针；不支持的语义保留并选择兼容后端或标记不可执行，不能删条件换取通过。
- 对照独立预期比较完整目标结果集合、类型、关键中间事实和禁止结果，分别验证规则隔离与组合；负例先确认执行成功。具体设计与覆盖证据见[规则测试参考](rule-design-and-tests.md)。
- 每个能力问题指向公理/规则/查询、来源与案例；推理任务须有真实非空推导，纯查询按预期验收。设计通过与执行通过分别报告，未运行写 `not_run`；自然语言解释不作为确定性执行记录。
